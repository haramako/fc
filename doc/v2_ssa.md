# SSA による定数伝播 / コピー伝播 / DCE（第 4 弾の本命）

2026-09-20 設計・実装。`internal/opt/ssa.go`。ロードマップの「SSA 化（Braun 方式）+ 定数伝播 / コピー伝播 / DCE」。

## 1. 方針: IR は変えず、SSA は解析として持つ

fc の IR は「変数 + 命令列」で、regalloc（常駐レジスタ、A 割付、cond）と codegen はその形（`Value.LocalType`、
一時変数の「定義の直後に 1 回使う」パターン、`Home` の退避先…）に深く依存している。IR そのものを SSA（φ 命令入り）に
書き換えて out-of-SSA を書くと、その全部を作り直すことになる。

そこで **SSA は関数の CFG の上に作る解析** にした。各変数の「命令ごとの版」（`ssaVal`: 命令による定義 / φ / 引数の入口 /
未定義）と φ を Braun らの方法（*Simple and Efficient Construction of SSA Form*, CC 2013。支配辺境を計算せず、
読み出しの度に先行ブロックを遡って必要な所にだけ φ を置き、自明な φ は置いた端から消す）で求め、その結果で命令列を
書き換える。書き換えたら SSA は捨てて作り直す（関数は小さいので十分速い。castle 全体で数十 ms）。

出来ること:

- **定数伝播**: 版が定数なら使用位置をリテラルに。定数は定義の演算を畳んで求め、φ は全ての入力（自分自身と未定義を
  除く）が同じ定数のとき定数。ループの中で変わらない変数、両方の枝で同じ値を代入した変数も定数になる
- **コピー伝播**: 版が `load x = y` で、使用位置での y の版が同じ（間で y が書き換えられていない）なら x を y に。
  y はユーザーの変数か引数に限る（一時変数からのコピーは coalesceCopies / A 割付が「定義の直後の 1 回の使用」の形で
  扱うので広げない。常駐レジスタの候補も LTNone / LTArg だけなので、その形を保つ）
- **DCE**: 副作用の無い命令（`regalloc.DeleteUnuse` と同じ集合）の定義した版が、どこからも（φ を経由しても）使われなければ消す。
  ループの中で自分しか使わないカウンタも消える
- 定数になった `if` / `if_true` / `switch` は `jump` か削除に（届かなくなったコードは simplifyJumps が消す）

対象はスカラ（整数 / bool / ポインタ / 関数ポインタ）のローカル変数だけ。一部だけ書かれる変数（struct のフィールド、
2 バイトの半分への `CastedValue` の書き込み）、アドレスを取られた変数（`ref`）、配列、戻り値（return が暗黙に読む）は
対象外。グローバル変数は読み書きの省略が volatile や呼び出しとの順序に関わるので、この段では触らない（§4）。

## 2. 定数の読み方は codegen に合わせる

リテラルの型は演算の型と違うことがある（`255 / i10`（sint8）はリテラルが uint8 の 255 のまま渡り、codegen はその
バイト $ff を sint8 の -1 として割る。test_op の `assert_equal(255 / i10, -1)` で発覚）。畳み込みは codegen と同じ規則で
入力を読む:

- リテラルは整数値そのもの（型に関係なく値のバイトを取り出す: -1 を 16 ビットの演算に渡すと $ffff）。変数は自分の
  サイズに切り詰めたビット列（それより広い演算ではゼロ拡張。符号付きを広げるときは sema が `sign_extension` を挟む）
- 加減算・論理演算・乗算は結果の幅のビット列だけで決まる。除算・剰余は結果の型の符号、シフトは第 1 入力の符号、
  比較は「どちらかが符号付きなら符号付き」で幅は広い方（`lt` の codegen と同じ）、`!` は入力の型の幅で全バイト 0 か
- 版の値は変数のサイズに切り詰めたビット列で持ち、使用位置の型（`CastedValue` なら Offset バイト目からその型）で読む

## 4. 代数の簡約（`ssa.simplify`、2026-09-20）

版の定義を辿れるので、演算の連鎖を 1 つにまとめる（符号なしだけ）: `mul (div y, 2^k), 2^k` → `and y, ~(2^k-1)`、
`and` / `or` / 同じ向きのシフトの連鎖。中間の版 x の定義から y を取るので、使用位置でも y が同じ版でなければならない
（`sameOperandAt`。グローバルは間で書き換わりうるので不可）。castle の `bg.cell_type` / `my.get_cell` の `y / 16 * 16`
（`lsr` ×4 + `asl` ×4）が `and #$f0` になり、フレーム −3.4%（field 9115 → 8808、area33_idle 12862 → 12397）。

ついでに `coalesceCopies` を「同じサイズの整数型」にも広げた（`var dir:sint8 = p1[i]` の uint8 配列からの load。
結果が Dst の符号で変わる div / mod は除く）。

## 5. 誘導変数の統合（`internal/opt/induction.go`、2026-09-20）

ループの中で同じ歩幅で進む 2 つの変数のうち、比較にしか使われないカウンタ k をポインタ q の比較に置き換えて消す
（sieve の内側ループ `*q = 0; q += prime; k += prime; while (k < SIZE)` の `k += prime`（16 ビットの加算 20 サイクル）が
消える）。変換は induction.go の頭のコメントの通り: 入口で `lim = q + (LIM - k0)` を計算し、ヘッダの `k < LIM` を
`q < lim` に。k0 がリテラルでなければ入口で `k0 < LIM` を 1 度検査する（LIM - k0 が負になって lim が q の下に
回り込むのを防ぐ）。

正しさの根拠が 2 つ要る:

- **k が折り返さない**: LIM + (歩幅の上限) が k の型に収まること。歩幅の上限は `maxValue`（リテラル、型の最大値、加算なら
  入力の上限の和、ループの変数（φ）なら「その位置を支配する `lt t = v, LIM'; if` の真の側」から LIM' − 1）。sieve の
  `prime = i + i + 3` は外側のループの `i < 8191` から 16383 以下と分かり、8191 + 16383 < 65536 で通る。
  歩幅の型がカウンタと同じ幅で上限が分からなければ変換しない（`TestInductionNotApplicable`）
- **q + (LIM − k0) がポインタとして折り返さない**: 「ポインタ演算は配列の末尾 + 1 まで」という言語の規則
  （language_reference.md §6。C と同じ。この変換のために明文化した）から従う。lim ≤ 最後に触る q + 歩幅 = 元のプログラムが
  計算する q の最終値 ≤ 配列の末尾 + 1

SSA の上で書く理由: 「k のループ内の定義は毎周 1 回の加算だけ」「比較の時点で k も q も加算前の版」「ループの外の k の
使用がループを通った版を読まない（次のループで `i = 0` し直して使うのはよい）」が版の比較で書ける。
coalesceCopies の後に走らせる（`i += s` が `add i = i, s` になってから）。

結果: sieve −15.9%（17.9M → 15.1M サイクル。内側ループが `sta (q),y; q += prime; cmp 16 ビット; bne`）。
crc8 / crc16 の main のバッファを埋めるループも対象になった（サイズ +1 バイト、サイクルは変わらず）。castle には形が無い。
実行テストは `TestInductionRun`（入口の検査でループに入らない場合、歩幅が変数の場合、初期値がリテラルの場合を -O 0 と比べる）。

**上限が変数のとき**（2026-09-24）: `i < length` のように LIM がループの中で定義されない符号なしの変数でも、歩幅がリテラルの
1 なら置き換える（k < LIM ≤ 型の最大値 なので k + 1 は折り返さない。k0 が 0 なら `lim = q + LIM`、0 でなければ入口で 1 度
だけ元の検査をして `lim = q + (LIM - k0)`）。crc8 / crc16 の本体のループ（上限が引数）が対象になり、crc8 −8.0%、crc16 −3.9%。

## 6. 小さなループの完全展開（`internal/opt/unroll.go`、2026-09-20）

Oscar64 の crc8 が fc の 3 倍速い（0.4 s vs 1.19 s）のは `for (j = 8; j; j--)` を展開して `asl; bcc; eor` を 8 つ並べる
から（48 サイクル/バイト）。回数がリテラルから決まる短いループを本体の写しの並びにする:

- ヘッダは「ラベル + [`lt` / `eq t = k, リテラル`] + 分岐」、k はループ内で毎周 1 回 `add / sub k = k, リテラル` でしか
  変わらず初期値がリテラル。回数はシミュレーション（ヘッダの条件を k の値で評価）で求め、8 回まで。
  コードになる命令数 × 回数 ≤ 64
- 各写しにヘッダの検査を残す（k が定数になるので SSA が消す。畳めなくても正しい）。本体の中の `goto L`（continue）は
  次の写しのヘッダへ、ループの外へのジャンプはそのまま。写しのラベルは `元のラベル_<関数内で未使用の番号>`
  （`_u1` のような固定の接尾辞にすると、先に展開した内側のループの写しと衝突した。fuzz の種 15 で発覚）
- ループ内で定義・使用される一時変数は写しごとに別の変数にする（同じ一時変数を何度も定義すると live range が伸びて
  A / フラグへの割付が外れる）。ユーザーの変数（`crc`）はそのまま
- for の出口ブロック（`@else: jump @end`）は本体と step の間に置かれるので、ループの範囲にループ外のブロックがあってもよい
  （そこからループへ入らなければ。写しごとに一緒に写す）

結果: crc8 −30%（内側が `asl a; bcc; eor #29` ×8、crc は外側のループでも A に常駐）、crc16 −14.6%、bgdecode −3.0%、
oam −2.8%、castle フレーム −0.7%（24 ループ）。サイズは crc16 +43%、oam +24%、castle の ROM +1.5 KB（+1.7%）。
`FC_DISABLE=unroll`、`FC_TRACE_UNROLL=1`（対象外の理由と展開したループ）。

副産物: `regalloc.isMemShift`（「メモリ上の定数シフトは A を使わない」の判定）が、別の場所への写し・2 バイトの 8 以上の
シフト（バイトの移動）・符号付きの右シフトを含めていて、x.hi を A に常駐させたまま `x >> 8` が A を壊していた
（TestSplitWords の mix が SSA のコピー伝播で形が変わって発覚。`TestResidentMemShift`）。

## 7. 関数ポインタ表の呼び出しの直接化（`internal/opt/devirt.go`、2026-09-20）

`TBL[i](args)`（TBL は const の表で要素が全部関数）を `switch i` + 直接呼び出しに書き換える。間接呼び出し
（表からポインタを読んで `jmp (ptr)`、引数はスタック経由で呼び先の Entry プロローグがフレームに写す）が、ジャンプ
テーブル + `jsr f__direct`（引数はフレームに直接、最後の引数は A、戻り値は A）になる。`InlineProgram` の後・
`frames.Analyze` の前（直接の辺として呼び出しグラフに載る）。表は 16 要素まで、push と call の間に他の呼び出しが
無い形だけ、far になる呼び先は `Far` を付ける。`calls` −5.6%（表経由の 500 回）。

castle の `en_vtbl.PROCESS` は 83 要素なので対象外にした。83 の case を作ると 1 か所 800 バイト前後（2 か所で
1.6 KB）で、得は 1 呼び出し 30 サイクル程度（16 体で 4%）。ROM を払うなら上限を上げれば効く。

副産物: switch 命令のジャンプテーブルは添字に X を使っていたが、stack 関数（再帰）では X がフレームポインタなので
壊れていた（devirtualization で再帰する関数に switch が入って発覚。stack 関数では Y を使い、regalloc は switch を
Y の clobber と見る）。

## 8. 小さな関数の自動インライン（`internal/opt/inline.go`、2026-09-20）

`options(inline: true)` の仕組み（`InlineProgram`）に、印の無い関数も条件を満たせば載せる。条件（`autoInlinable`）:
本体の命令数（ラベル・jump を除く）が 12 以下で、ループ・呼び出し・asm・アドレス取得（`&f`）・配列 / struct のローカルが
無く、extern / interrupt / `segment` / `symbol` / `abi` の指定が無いもの。そのうち 6 命令以下なら呼び出し箇所がいくつ
あっても展開し、それより大きいものは呼び出し箇所が 2 以下のときだけ（ROM を増やさないため）。`options(noinline: true)`
で個別に止められる（テストで「関数が出力されること」を見るときに使う）。`FC_DISABLE=autoinline`。

結果: `calls` −22%（`add8` などの小さな呼び先が全部消える）、`entities` −16%（`bounce` などの 1〜2 か所から呼ぶ
関数。ROM は +43%）、castle は ROM +1.6 KB（0.7%）で field 8636→8615、area33_jump 14207→14186 サイクル。
stdio の `bench_start` / `exit` などが main に入るので、bench の module 別サイズは +32 になるが ROM 全体は減る。

副産物: const で別名を付けた関数（`const D2 = f;` の f）は inline で呼び出しが消えても出力が要る。`frames.Analyze`
の到達判定に DefEqu の別名を根として足した（`_test_var__D2` が未定義になった）。

**バンクをまたぐ展開の条件**（2026-09-21）: 別モジュールへの展開は「本体に呼び出しが無い」だけでは足りず、本体が触る
データが写した先から見えることが要る（`opt.dataReachable`）。RAM（`var` = DefBss、数値の `address:`）はどこからでも見える。
ROM（const の表 = DefBlock、関数内の文字列などの `Lambda.Defs`）はその持ち主のモジュールが固定バンクか、写す先と同じ
モジュールのときだけ。asm のシンボルに束縛したもの（DefExtern）と `segment:` 付きの caller は置き場所が分からないので不可。
ポインタの指す先は呼び出しのままでも同じ条件なので見ない。切替バンクの表を読む小関数（明示 inline / 自動 inline）が
別バンクに写ってコードだけ移り、far call のバンク切替も消えて別の表を読んでいた（castle の実機で発覚。emu の fuzz には
バンクが無いので見えず、`internal/driver/bank_test.go` に MMC3 の内蔵 NES ランナーで走らせる `TestInlineAcrossBanks` と
小さな fuzz `TestRandomBankPrograms` を足した）。

**asm を含む本体の別モジュールへの展開**（2026-09-24）: 別モジュールへは呼び出しと同じく asm を含む本体も写さない
（中身を解析しないので、中で `jsr` したり元のモジュールだけに見えるシンボルを参照したりしうる）。ただしフラグだけを
変える命令（`sei` / `cli` / `clc` / `sec` / `cld` / `sed` / `clv` / `nop`）だけの asm は写す（`opt.flagOnlyAsm`）。
自動インラインは asm を含む関数を最初から対象にしないので、効くのは `options(inline: true)` の関数だけ。
castle の `mmc3.set_pbank`（`sei` / `cli` を含む）を inline にして、`en.process` の敵ごとのバンク切替の呼び出しが
消えた（area8b −2.7%、ROM −417 バイト）。

## 9. 添字の定数オフセットの畳み込み（`internal/opt/indexoff.go`、2026-09-20）

`a[i + k]`（k は定数、a はグローバルの要素 1 バイトの配列）の `add t = i, #k; index_pget / index_pset a, t` を
`index_pget / index_pset <k>a, i`（配列のオペランドを Offset k の CastedValue に）にして、codegen が `lda a+k,y` /
`sta a+k,y` を出す。Y に置いた添字 i がそのまま使えるので `clc; lda i; adc #k; tay`（約 10 サイクル）が消え、castle の
OAM への `buf[idx+1] … buf[idx+3]` が手書き asm の `iny` 相当になる。fusePointer の後（index + pget / pset が
index_pget / index_pset になってから）。一時変数 t は定義 1 つ・使用が添字だけ、定義から使用まで直線で i が
書き換わらないもの。使用が全部置き換わったら add を消す。

言語の規則を 1 つ足した（language_reference.md §6）: 添字の式 `i + k` は 8 ビットで折り返さない（`i + k > 255` は範囲外の
添字と同じ未定義）。折り返しを当てにするリングバッファは変数で進める（`j = i + k; a[j]`）。

効果: bgdecode −11.7%、castle（実プロジェクト）field 8634→8520、`ppu.sprite_idx` 166→103 サイクル（fc に書き直して
asm より遅くなっていた分が逆転）、ROM −323 バイト。

## 10. 1 ずつ進むポインタの下位を Y で回す（`internal/opt/ywalk.go`、2026-09-24）

ループの回転の後（`jumps` の後の段 `ywalk`）で、`*p` / `p += 1` だけで使われるポインタの下位バイトを添字の変数 `$k` に移す。
ループの間は p の下位を 0 にして、本当の値は (p の上位, k)。`$k` はユーザーの変数と同じ扱いにして常駐の候補にする
（regalloc は一時変数を常駐させない）ので Y に乗り、

	lda (p),y          ; *p                (以前は ldy #0; lda (p),y)
	iny                ; p += 1            (以前は inc p; bne; inc p+1)
	bne @skip
	inc p+1
	@skip:
	cpy lim            ; p != lim で帰る   (以前は 16 ビットの `<`: lda; cmp; lda; sbc)
	bne @body
	lda p+1
	cmp lim+1
	bne @body
	@exit: sty p       ; 出口で p の下位を戻す

帰りの検査を `!=` にしてよいのは、p がループの中で毎周ちょうど 1 回 `p += 1` され、前の周の検査で p < lim だったので、
検査の時点で p <= lim だから。入口は元の `<` で 1 度検査する（1 回も回らないとき、p の下位はまだ k と同じなので出口の
`sty` はそのままでよい）。条件: p はアドレスを取られないローカルの 1 バイト要素のポインタ（呼び先からは見えないので、
ループの中の呼び出しはよい）で、ループの中の使用は `pget` / `pset` の番地と加算だけ。加算は毎周必ず通る: 本体の先頭にある
（そこまでにラベルも分岐も無い。このときは continue もよい）か、加算の後ろから帰りの検査までにラベルが無く continue が無い。
break / return / asm が無い。lim はリテラルかループの中で定義されない値。fuzz の生成器には、この形を狙う `walkLoop`
（300 バイトのバッファを 17〜290 回なめる。回数が 8 以下の既存のポインタのループは展開されて対象にならない）を足した。

副産物: ピープホールの `iny; cpy #0; bne` の `cpy` を消す規則が一度も効いていなかった（最初の switch が `cpy` を「フラグを
別の値で立てる命令」として `flagsFromY` を先に落としていた）。`cpx` と同じ位置で扱うように直して oam −2.4%。

結果（段階 1 の誘導変数の拡張と合わせて、2026-09-24 の前との比較）: crc8 819,583 → 664,093（−19.0%）、crc16 1,672,514 →
1,517,052（−9.3%）、sieve 15,066,104 → 13,922,084（−7.6%。効くのは初期化のループだけで、外側のループは `q = p + prime`
で p をそのまま使うので対象外）、oam −2.4%。castle には形がほとんど無く変わらない。crc8 は A に crc が常駐していて
`lda (p),y` が A を使うので k が Y でなく X に乗る（`stx; ldy; lda (p),y; ldx`）。読み出しを `eor (p),y` に融合できれば
さらに縮む。実行テストは `TestPointerWalkY`（ページをまたぐ長さ、1 回も回らない入口、ループの後の p、continue のある
対象外の形）。

## 11. 次にできること（この基盤の上で）

- グローバル変数（volatile でない）と配列要素の読み出しの前送り: 呼び出し・ポインタ経由の書き込み・asm を障壁にして、
  `index_pset a[i] = t; … ; index_pget u = a[i]` の 2 つ目を t に（entities.update に 3 か所）。6502 では `lda a,y` と
  `lda t` の差が 1 サイクルなので、値が定数になる・A に残っている場合以外は効果が薄い
- 共通部分式（同じ `a[i]` の読み出しを 1 回に）、呼び出しをまたぐ mod/ref 解析（castle は呼び出しの間で `anim` などの
  グローバルを読み直している）
- 到達しない φ / 未定義の読み出しの警告（`let x; if c { x = 1 } use(x)` のような未初期化の使用）
