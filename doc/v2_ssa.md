# SSA による定数伝播 / コピー伝播 / DCE（第 4 弾の本命）

2026-09-20 設計・実装。`internal/opt/ssa.go`。ロードマップの「SSA 化（Braun 方式）+ 定数伝播 / コピー伝播 / DCE」。

## 1. 方針: IR は変えず、SSA は解析として持つ

fc の IR は「変数 + 命令列」で、regalloc（常駐レジスタ、A 割付、cond）と codegen はその形（`Value.LocalType`、
一時変数の「定義の直後に 1 回使う」パターン、`Home` の退避先…）に深く依存している。IR そのものを SSA（φ 命令入り）に
書き換えて out-of-SSA を書くと、その全部を作り直すことになる。

そこで **SSA は関数の CFG の上に作る解析** にした。各変数の「命令ごとの版」（`ssaVal`: 命令による定義 / φ / 引数の入口 /
未定義）と φ を Braun らの方法（*Simple and Efficient Construction of SSA Form*, CC 2013。支配辺境を計算せず、
読み出しの度に先行ブロックを遡って必要な所にだけ φ を置き、自明な φ は置いた端から消す）で求め、その結果で命令列を
書き換える。書き換えたら SSA は捨てて作り直す（関数は小さいので十分速い。castle 全体で数十 ms）。

出来ること:

- **定数伝播**: 版が定数なら使用位置をリテラルに。定数は定義の演算を畳んで求め、φ は全ての入力（自分自身と未定義を
  除く）が同じ定数のとき定数。ループの中で変わらない変数、両方の枝で同じ値を代入した変数も定数になる
- **コピー伝播**: 版が `load x = y` で、使用位置での y の版が同じ（間で y が書き換えられていない）なら x を y に。
  y はユーザーの変数か引数に限る（一時変数からのコピーは coalesceCopies / A 割付が「定義の直後の 1 回の使用」の形で
  扱うので広げない。常駐レジスタの候補も LTNone / LTArg だけなので、その形を保つ）
- **DCE**: 副作用の無い命令（`regalloc.DeleteUnuse` と同じ集合）の定義した版が、どこからも（φ を経由しても）使われなければ消す。
  ループの中で自分しか使わないカウンタも消える
- 定数になった `if` / `if_true` / `switch` は `jump` か削除に（届かなくなったコードは simplifyJumps が消す）

対象はスカラ（整数 / bool / ポインタ / 関数ポインタ）のローカル変数だけ。一部だけ書かれる変数（struct のフィールド、
2 バイトの半分への `CastedValue` の書き込み）、アドレスを取られた変数（`ref`）、配列、戻り値（return が暗黙に読む）は
対象外。グローバル変数は読み書きの省略が volatile や呼び出しとの順序に関わるので、この段では触らない（§4）。

## 2. 定数の読み方は codegen に合わせる

リテラルの型は演算の型と違うことがある（`255 / i10`（sint8）はリテラルが uint8 の 255 のまま渡り、codegen はその
バイト $ff を sint8 の -1 として割る。test_op の `assert_equal(255 / i10, -1)` で発覚）。畳み込みは codegen と同じ規則で
入力を読む:

- リテラルは整数値そのもの（型に関係なく値のバイトを取り出す: -1 を 16 ビットの演算に渡すと $ffff）。変数は自分の
  サイズに切り詰めたビット列（それより広い演算ではゼロ拡張。符号付きを広げるときは sema が `sign_extension` を挟む）
- 加減算・論理演算・乗算は結果の幅のビット列だけで決まる。除算・剰余は結果の型の符号、シフトは第 1 入力の符号、
  比較は「どちらかが符号付きなら符号付き」で幅は広い方（`lt` の codegen と同じ）、`!` は入力の型の幅で全バイト 0 か
- 版の値は変数のサイズに切り詰めたビット列で持ち、使用位置の型（`CastedValue` なら Offset バイト目からその型）で読む

## 3. 結果（2026-09-20）

- bench: sieve -1.3%、bgdecode -0.6%（サイズ -11.6%）、calls サイズ -0.8%。他は変化なし（castle の形のベンチは
  もともと定数が少ない）
- castle: フレームあたり field 9123 → 9115、area33_idle 12894 → 12862、area33_jump 15008 → 14971（-0.1〜0.3%）
- test_op / test_alloc などの unittest はほとんど畳まれて消えた（test_op.bin 7736 → 5779 バイト）。**そのままでは codegen の
  検証にならないので `TestGoldenStdoutO0` を足した**（同じプログラムを `-O 0` で走らせて同じ stdout を要求する）
- 副産物: `!` の 2 バイトの入力の codegen がバイトごとに `beq` していて「どれかが 0」になっていた（`!l1` が l1 = 1 で 1）。
  両方のレベルで同じ結果だったので差分テストでは見つからず、SSA の畳み込みと食い違って発覚（`TestNot16`）
- fuzz: 2000 本（種 20000〜、30000〜）で食い違いなし

## 4. 代数の簡約（`ssa.simplify`、2026-09-20）

版の定義を辿れるので、演算の連鎖を 1 つにまとめる（符号なしだけ）: `mul (div y, 2^k), 2^k` → `and y, ~(2^k-1)`、
`and` / `or` / 同じ向きのシフトの連鎖。中間の版 x の定義から y を取るので、使用位置でも y が同じ版でなければならない
（`sameOperandAt`。グローバルは間で書き換わりうるので不可）。castle の `bg.cell_type` / `my.get_cell` の `y / 16 * 16`
（`lsr` ×4 + `asl` ×4）が `and #$f0` になり、フレーム −3.4%（field 9115 → 8808、area33_idle 12862 → 12397）。

ついでに `coalesceCopies` を「同じサイズの整数型」にも広げた（`var dir:sint8 = p1[i]` の uint8 配列からの load。
結果が Dst の符号で変わる div / mod は除く）。

## 5. 誘導変数の統合（`internal/opt/induction.go`、2026-09-20）

ループの中で同じ歩幅で進む 2 つの変数のうち、比較にしか使われないカウンタ k をポインタ q の比較に置き換えて消す
（sieve の内側ループ `*q = 0; q += prime; k += prime; while (k < SIZE)` の `k += prime`（16 ビットの加算 20 サイクル）が
消える）。変換は induction.go の頭のコメントの通り: 入口で `lim = q + (LIM - k0)` を計算し、ヘッダの `k < LIM` を
`q < lim` に。k0 がリテラルでなければ入口で `k0 < LIM` を 1 度検査する（LIM - k0 が負になって lim が q の下に
回り込むのを防ぐ）。

正しさの根拠が 2 つ要る:

- **k が折り返さない**: LIM + (歩幅の上限) が k の型に収まること。歩幅の上限は `maxValue`（リテラル、型の最大値、加算なら
  入力の上限の和、ループの変数（φ）なら「その位置を支配する `lt t = v, LIM'; if` の真の側」から LIM' − 1）。sieve の
  `prime = i + i + 3` は外側のループの `i < 8191` から 16383 以下と分かり、8191 + 16383 < 65536 で通る。
  歩幅の型がカウンタと同じ幅で上限が分からなければ変換しない（`TestInductionNotApplicable`）
- **q + (LIM − k0) がポインタとして折り返さない**: 「ポインタ演算は配列の末尾 + 1 まで」という言語の規則
  （language_reference.md §6。C と同じ。この変換のために明文化した）から従う。lim ≤ 最後に触る q + 歩幅 = 元のプログラムが
  計算する q の最終値 ≤ 配列の末尾 + 1

SSA の上で書く理由: 「k のループ内の定義は毎周 1 回の加算だけ」「比較の時点で k も q も加算前の版」「ループの外の k の
使用がループを通った版を読まない（次のループで `i = 0` し直して使うのはよい）」が版の比較で書ける。
coalesceCopies の後に走らせる（`i += s` が `add i = i, s` になってから）。

結果: sieve −15.9%（17.9M → 15.1M サイクル。内側ループが `sta (q),y; q += prime; cmp 16 ビット; bne`）。
crc8 / crc16 の main のバッファを埋めるループも対象になった（サイズ +1 バイト、サイクルは変わらず）。castle には形が無い。
実行テストは `TestInductionRun`（入口の検査でループに入らない場合、歩幅が変数の場合、初期値がリテラルの場合を -O 0 と比べる）。

## 6. 次にできること（この基盤の上で）

- グローバル変数（volatile でない）と配列要素の読み出しの前送り: 呼び出し・ポインタ経由の書き込み・asm を障壁にして、
  `index_pset a[i] = t; … ; index_pget u = a[i]` の 2 つ目を t に（entities.update に 3 か所）。6502 では `lda a,y` と
  `lda t` の差が 1 サイクルなので、値が定数になる・A に残っている場合以外は効果が薄い
- 共通部分式（同じ `a[i]` の読み出しを 1 回に）、呼び出しをまたぐ mod/ref 解析（castle は呼び出しの間で `anim` などの
  グローバルを読み直している）
- 到達しない φ / 未定義の読み出しの警告（`let x; if c { x = 1 } use(x)` のような未初期化の使用）
