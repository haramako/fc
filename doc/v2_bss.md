# V2: モジュール・ブロックの BSS 配置

2026-09-20。`codex/v2-bss-placement` で実装し、コミット `0e539d8` を元ブランチへマージ済み。
元ブランチはその後 `main` に改名された。V3 の構文変更とは独立した V2 の追加機能。

```fc
options(bss: "BSS_EX");
var a:int;
block {
    public var b:int;
    var c:int options(segment: "BSS");
} options(bss: "IRQ_DATA");
```

## 確定した扱い

- 既定値のキーはモジュール・配置ブロックとも `bss`。個別変数は既存の `segment` を維持する。
- 個別 `segment`、内側のブロック、外側のブロック、モジュール、通常 `BSS` の順に優先する。
  明示的な `segment: "BSS"`（および従来の空文字指定）は継承を止め、通常の BSS に置く。
- モジュール属性はファイル全体へ適用し、後の宣言だけへの切替にはしない。複数指定は最後の値が全体に効く。
- `use` 先には伝播させず、依存モジュールの指定も呼び出し側に漏らさない。`Program.Options` には `bss` を格納しない。
- 配置ブロックは名前空間を増やさない。変数の名前・公開範囲・寿命は通常のグローバル宣言と同じ。
- ブロック内は `var`、可変 `soa`、入れ子の配置ブロック、空文を許可する。
  関数・const・soa const・use・include・単独 options 文・実行文はエラーとする。
- 関数内に配置ブロックは置けない。ローカル変数の静的フレームや再帰スタックには適用しない。
- 固定アドレス変数は元どおり equ を生成し、BSS を確保しない。
- 可変 soa の各フィールド配列に継承する。個別 soa の `segment` は継承を上書きする。
- `bss` は空でない文字列を要求し、asm の文字列を壊す制御文字・引用符・バックスラッシュを拒否する。
- `block` は文脈依存で認識し、予約語にはしない。フォーマッタと構文木走査も対応する。

## リンカ・起動処理との境界

メモリマップは既存の ld65.cfg で管理する。標準設定にないセグメントは利用者の cfg に定義する。
未知のセグメント名は従来と同様にリンクで検出する。FC が領域や起動時ゼロクリアを自動追加することはない。
保存 RAM の扱いを変えず、連続配置・ページまたぎ防止も別機能として扱う。

**コード配置についての補足:** 現行の関数自身の `options(segment: ...)` は有効。
一方、現行コード生成は既定のコードセグメントをモジュール名から決めており、
モジュール単独の `options(segment: ...)` はコードの既定配置を変更しない。
以前の検討時の説明をここで訂正する。今回の BSS 追加ではこの既存挙動に手を加えない。

## 実装と検証

- 構文: `internal/syntax` の PlacementBlock、文脈判定、parser.y と再生成 parser.go、formatter、Children。
- 意味解析: 配置ブロックの既定値を退避・復帰し、通常変数と可変 soa に適用する。
  モジュール既定値はトップレベル宣言の処理後、未指定の DefBss に適用して宣言位置に依存させない。
- テスト: 属性の優先順位、入れ子からの復帰、依存モジュールの独立性、公開変数、soa、固定アドレス・ROM 定数・ローカルの除外。
- テスト: 不正な指定位置・値・ブロック内容の診断、コメントを含む整形の往復と位置、既存 block 識別子・構造体リテラル。
- 結合テスト: 実際に ca65 / ld65 でリンクしたシンボルのセグメントを確認し、emu で読み書きの結果を検証する。

## 将来に残す検討

ブロックへの関数・const 等の許可、コード配置を含む複数の既定属性、自動セグメント生成、ページ内配置は含めない。
今回の BSS 配置を使うために、これらを先に決める必要はない。
