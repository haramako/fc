# emphasis-fade-test

## 目的

PPUMASK の強調ビットを 3 つとも立てて、`pal.fade` の明るさの段の間に半段を挟めるかを確かめる NES の ROM。
相談の経緯は `Agent/discussions/2026-10-01-pal-fade-emphasis.md`。

## ファイル

- `emphasis.fc` … ROM のソース（fc 4、fclib の frame / vram / pal / oam / pad）
- `swatch.chr` … 色 1〜3 の塗りつぶしのタイル 3 枚（48 バイト。内蔵のフォントの後ろ、タイル 0x80〜0x82 に入る）
- `measure.lua` … Mesen の testrunner で段ごとの色見本の色を出す
- `screenshot.png` … Mesen の画面（段 8、分割が on）

## 実行

```bash
fcc build -t nes -g -o emphasis.nes emphasis.fc
Mesen.exe emphasis.nes                        # 手で見る
Mesen.exe --testrunner emphasis.nes measure.lua   # 段ごとの色を出す (Mesen が起動中だと動かない)
```

## 画面と操作

- 色見本: 行は青・赤・灰、列は同じ色相の $3x / $2x / $1x / $0x（灰は $30 / $20 / $10 / $00）
- 上の色見本は、今の段の明るさと強調で出る。下の色見本は、分割が on なら常に強調を足す
  - スプライト 0 の当たり（15 行目の左端）を主の側で待ち、PPUMASK を書き換えて分割している
- 段は 0（黒）〜 8（元の色）。偶数は `pal.bright(段 / 2)`、奇数は `pal.bright((段 + 1) / 2)` に強調を足したもの
- LEFT / RIGHT: 段を変える。A: 強調なしで 8 → 0 → 8 とフェードする（1 段 8 フレーム）。B: 強調ありの 9 段でフェードする（1 段 4 フレーム）。SELECT: 分割の on / off

## 結果（2026-10-01、MesenCE 2.2.1 の既定のパレット、`measure.lua`）

- 強調は RGB が約 0.70 倍になる（$30 の fffeff が b3b3b3、$10 の adadad が 7a7a7a）。Mesen の既定のパレットの近似で、NESdev の NTSC の電圧の値（0.816 倍）とは別の計算
- 段ごとの色から輝度 Y（0.299R + 0.587G + 0.114B）を計算した結果:

| 段 | 8 | 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |
|---|---|---|---|---|---|---|---|---|---|
| 青 $31 | 217 | 153 | **162** | 114 | 87 | 61 | 40 | 28 | 0 |
| 赤 $36 | 218 | 153 | **164** | 116 | 87 | 60 | 36 | 25 | 0 |
| 白 $30 | 254 | 179 | **254** | 179 | 173 | 122 | 102 | 71 | 0 |

- 段 7（$3x + 強調）は段 6（$2x）より暗い。8 → 7 → 6 で一度暗くなってから明るく戻る
- 白は `pal.shade` で $30 → $20 になるが、$20 と $30 は同じ白なので、8 → 7 → 6 → 5 → 4 が「白 → 灰 → 白 → 灰 → 灰」とちらつく
- 色つきの色は、段 5 以下（$2x 以下）で半段が前後の段の間にきちんと入る。白は段 5（179）と段 4（173）がほぼ同じ

## 制約

- Mesen の既定のパレットでの結果。実機（とくにブラウン管）や、ほかのパレット・エミュレータでは数値が変わる
- 色見本の真ん中の 1 画素だけを見ている
