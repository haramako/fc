# 実行のときの検査（サニタイザ、internal/san）

確かめた日: 2026-11-15（下の数は 4bae8fa の上で測った）。

## なぜ

差分テスト（-O 0 / -O 2 / IR インタプリタ）と模型つきの生成器は「出力が同じか」しか見ない。壊れても出力に出ない誤り
（フレームの重なりが、たまたま使わない値を壊すだけ）と、生成器が出力に使わない値の誤りは通る。内蔵の 6502 で走らせながら、
出力と関係なく「起きてはいけないこと」を見る。

## 検査（emu ターゲット、静的フレームの関数）

- **フレームの重なり**: 関数に入るとき、そのフレームが実行中のほかの関数のフレームと重ならない。同じ関数に入り直さない
- **未初期化の値の使用**: 関数に入るとフレーム（引数を除く）は未初期化、戻ると（戻り値を除いて）未初期化。印は値と一緒に伝わり
  （レジスタ・フラグ・メモリ・ハードウェアスタック）、その値で**分岐する・番地や添字に使う・出力の番地（$fff0〜）に書く**ときに
  誤りにする。印は出どころ（どの関数のフレームの何バイト目か）を持ち、報告に出す

読むだけ・写すだけで誤りにしないのは、正しいコードがそうするから（条件つきで代入する変数をループの前にレジスタへ載せる、
一部だけ初期化した struct を値で渡す）。初めの版は「未初期化のバイトを読んだら誤り」で、既存のテストの正しいプログラム 2 本が
掛かった。

積んだ引数を、呼ぶまでの間にほかの関数（引数の式の中の呼び出し。兄弟の関数のフレームは重ねて置く）が使うと、その関数が戻った
ときに未初期化になるので、呼び先がその引数を使う所で見つかる（別の検査は要らない）。

## 形

- `san.Checker` は `r6502.Bus` を包む。`Step(cpu)` を命令の前に呼ぶ: 呼び出しの出入り（入口の番地と S。入ったときの S より S が
  大きくなったら戻った。同じ S で別の関数の入口なら末尾の jmp）を追い、命令を自分で読んで印を伝える。書き込みの印は `Set` が入れる
- `san.Info`（関数の入口・フレームの番地と大きさ・引数と戻り値の位置）は driver の `sanInfo` が、リンクの後の `ir.Lambda`
  （`FrameBase`・`Conv`）と dbgfile の番地（`FC_SZP` / `FC_SRAM`・関数のシンボル）から作る（`BuildOptions.Sanitize` → `Result.San` →
  `runner.Options.San` → `emu.Options.San`）。san は r6502 だけに依る（emu がコンパイラの側を import しないように）
- テストの `testBuild` は emu で走らせるビルドで既定で有効（fuzz・golden・例の全部に掛かる）。切るのは `buildSpec.NoSan`
  （わざと未初期化の値を出すテスト）か環境変数 `FC_NO_SAN=1`

## 確かめたこと

- 駆動部のテスト全体と、日付の種の fuzz 10 種 × 600（`-randseed 20261115000`）で、今のコンパイラに報告は 0。時間は検査なし
  59.1 秒・あり 59.4 秒
- 対照（コンパイラをわざと壊す。fuzz 5 種 × 150）:
  - RAM のフレームを呼ぶ側に 2 バイト重ねる（frames.Place）: 検査なしで落ちるのは 8 本、検査ありは 114 本
  - 引数の式の「下ろすと呼び出しになる式」を数えない（billiards で見つかった誤りを戻す）: fuzz ではどちらも 0（生成器がこの形を
    作らない）。回帰テスト（TestFloatRun の floating_args）では検査も「ほかの関数のフレームの未初期化の値で分岐」と報告する
- 検査器だけの単体テスト: `internal/san` の TestChecker（手で組んだ 6502 のコード 12 例）

## まだ無いもの

- NES（`internal/nes`）: バンクを切り替えると同じ番地に別の関数が来るので、入口を番地だけで引けない。入っていないバンクの
  実行・読み出し、割り込みからの入り直し、描画中の PPU の書き込みもここで見る
- stack の関数（再帰）のフレーム、グローバル変数（起動のときに 0 にするので初期化済みとして扱う）
- 利用者向けのコマンド（`fcc run` のオプション）
