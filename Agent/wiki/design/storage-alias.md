# V2 型付きストレージ alias

2026-09-21。設計レビュー後、V2 / main に実装。アクティベーションによる自動共有配置は別の未実装案。

## 1. 目的

互いを知らないゲームの各モジュールが、一つのグローバル作業領域を独自の型で利用する。
共有領域側に全利用者の struct を列挙する必要をなくし、ポインタ変数の確保・設定・間接参照を追加しない。
使用するタイミング、割り込みとの排他、用途切替時の内容の初期化は利用者が管理する。

## 2. 構文

```fc
// shared.fc
public var work:[32]uint8;
```

```fc
// hoge.fc
use shared;

struct HogeWork {
    x:int;
    y:int;
    params:[4]int;
}

alias work:HogeWork = shared.work;

function init():void {
    work = {x:1, y:2}; // params も含めた HogeWork 全体を初期化する
}

function update():void {
    work.x += work.y;
}
```

別モジュールは自分の型で `alias work:MenuWork = shared.work;` と宣言できる。
`shared` から利用者への依存は生まれない。双方の alias 名が同じでもモジュールが違えば衝突しない。

文法は `[public] alias name:Type = target;`。型の明示を必須とし、宣言は一文一名とする。
`=` は初期値の代入ではなく、参照する記憶領域の指定。alias の再束縛はできない。
`alias` は宣言の形でだけ認識する文脈キーワードとし、既存の変数名・関数名としての使用を保つ。
構文解析へのトークン入力で `alias IDENT :` の形を先読みして識別する。

代案 `var work:HogeWork options(overlay: shared.work);` は領域を確保しない点が通常の var と異なるため採用しない案。
V3 の属性表記変更とは独立した V2 の追加機能とする。

## 3. 記憶領域と読み書き

- alias は新しい型でもポインタ型でもなく、既存の領域に対する型付きの変数名。
- RAM、ROM の初期値データ、起動時の処理を、宣言のために追加しない。
- 実体を確保するのは元の var 一つだけ。alias の数は確保サイズに影響しない。
- 宣言しただけではクリア・コピー・値変換を行わない。以前の用途のバイト列がそのまま残る。
- `work.x` は通常のグローバル struct のフィールドと同じ直接アクセスとして扱う。
  最適化レベル 0 でも、alias を理由とした実行時のポインタは生成しない。
- struct の配置・数値の解釈は既存の型規則どおり。現在の struct は宣言順に詰めて配置し、パディングなし。
- `&work` の型は `*HogeWork`、`sizeof(work)` は `sizeof(HogeWork)`。元の領域は依然として32バイト。
- `var copy = work;`、引数・戻り値の値渡しは通常の値コピー。alias の共有性がコピー先へ伝播するわけではない。
- 配列の可変添字や、取り出したポインタの参照には、既存の添字計算・ポインタアクセスのコストがある。
  alias はすべての式を固定番地の一命令にする機能ではない。

例えば `work.x = 1;` の格納先は、リンカが決める `shared.work` の先頭番地になる。
コンパイル時に数値の番地が決まっている必要はなく、アセンブラのシンボルと定数オフセットで表せればよい。

```asm
lda #1
sta _shared_work+0
```

`work = {x:1, y:2};` は HogeWork の全6バイトを代入し、残り26バイトは変更しない。
省略した params は全要素ゼロ。用途の切替自体に自動の初期化処理はない。
struct リテラルを即値の連続格納へ変換する最適化は別件とし、本機能では保証しない。
現在のように ROM 上の定数データから直接アドレスの領域へコピーする実装でも仕様を満たす。

## 4. 初版の対象とサイズ検査

対象は、名前またはモジュール修飾名で指定するグローバル var、あるいは別のストレージ alias。
右辺はアドレス式や値式ではなく、記憶領域を持つ宣言への参照として解決する。

```fc
alias a:HogeWork = shared.work; // 可
alias b:HogeWork = a;           // 可。同じ実体に正規化
```

右辺へのフィールド指定、配列添字、数値オフセットは初版に含めない。
局所変数・引数の領域、ポインタが指す領域、関数呼び出し結果、一時値、ROM 定数、SoA コンテナは対象外。
`alias h:HogeWork = ptr;` は ptr の指す領域にはならない。ptr がグローバル var なら、そのポインタ値を
格納する領域そのものが対象となり、通常のサイズ検査を行う。ポインタの自動参照はがしはしない。

alias の型は、サイズが確定した既存の記憶可能な型（整数・bool・ポインタ・fn/farfn・struct・固定長配列）。
void、長さ未指定配列、SoA は不可。初版は対象・alias ともにサイズが正であることを要求する。
異なる型間の代入互換性は要求しない。変換せずバイト列を共有する宣言だからである。

検査は `sizeof(alias の型) <= sizeof(直接の対象の型)` とする。
alias を経由した場合も、元の大きな領域を理由に中間の alias の範囲を越えることはできない。
実体・型・サイズの依存はコンパイル時に解決し、実行時のサイズ検査は入れない。

```fc
alias small:[4]uint8 = shared.work; // 可
alias large:[8]uint8 = small;       // 不可。対象 small は4バイト
```

固定アドレスのグローバル var も、その宣言サイズを利用して検査する。
外部ハードウェアの実際の領域サイズまでは保証しない。

## 5. スコープ、公開、宣言順

モジュール直下と関数内のブロックで宣言可能とする。
関数内の alias も対象はグローバル領域だけ。名前の有効範囲が局所的になるだけで、実体の寿命は変わらない。
関数内では宣言以降で利用でき、通常の局所名と同じ衝突・遮蔽規則に従う。

```fc
function update():void {
    alias h:HogeWork = shared.work;
    h.x += 1;
}
```

モジュール直下では既存の宣言収集・遅延解決に参加し、対象や型の後方宣言を許可する。
モジュールの相互参照は既存どおり可能だが、実体のない alias 循環は依存経路を添えてエラーにする。

`public alias` はモジュール直下のみ。`use name from mod`、`use * from mod`、再公開は既存の公開規則に合わせる。
公開 alias はその型と領域へのアクセスを公開するもので、実体の宣言名の公開状態は変更しない。
別モジュールの非公開な対象を直接指定することはできない。
公開された private 実体への alias は、提供モジュールが意図的にアクセスを公開したものとして利用できる。
型名の可視性は既存の public 変数と同じ規則に従う。

alias 独自の `address` / `segment` / `bss` / `symbol` / `volatile` 属性は初版に設けない。
配置と volatile 性は実体から引き継ぎ、別名を通して解除できない。
BSS 配置ブロックは現行の「確保する var / soa の配置をまとめる」用途に保ち、alias は初版では置けない。
asm 向けの公開シンボルを alias 宣言ごとに生成することも初版の範囲外。

## 6. 共有の意味と最適化の正しさ

同じ領域を参照するすべての名前は、型が違っても互いの書き込みを反映する。
「異なる struct 型だから重ならない」という仮定を置かない。

```fc
alias a:HogeWork = shared.work;
alias b:HogeWork = shared.work;

function example():int {
    a.x = 1;
    b.x = 2;
    return a.x; // 必ず 2
}
```

元の配列への書き込み、別モジュールの関数経由の書き込み、インライン化後も同じ規則。
alias 宣言そのものは volatile を付与しない。割り込み・外部 asm との共有は元の変数の既存規則に従う。
値代入では右辺を先に評価し、その値を左辺に格納する。同じ実体の alias / struct フィールド間で
異なるオフセットの領域が重複する場合は、右辺を一時値に退避してから書き込む。
生ポインタを介した任意の重複コピーの解析は本機能の対象外。alias のゼロコスト保証は「宣言と固定フィールドの参照」に対するもので、
重複コピーの退避や任意の式の評価コストまでなくす保証ではない。
型別の無効な表現や未初期化の関数ポインタ等は、既存の低水準メモリアクセスの規則を変えない。

## 7. 実装

- AST は VarDecl の Alias 属性で宣言を区別し、文脈キーワードの認識と formatter に接続した。
- Program.storageGlobals が実体を持つグローバル var、storageAliases が別名の束縛から正規化済みの実体を保持する。
- 別名の束縛は独立した型・名前・公開状態を持ち、Scope に登録する。IR の変数一覧や DefBss には登録しない。
- 式で別名を利用する際に、同じ元 Value の CastedValue へ変換する。既存の直接フィールド参照と部分書き込みの
  解析が働き、独立したグローバル変数として誤認しない。名前と型の解決は既存の遅延宣言解決に参加する。
- const として別名の実行時の値を読み出すことはエラー。sizeof は宣言した型のサイズとして評価できる。
- 重なる固定位置の struct コピーは必要な場合だけ右辺を退避する。
- デバッグ情報は既存の利用地点のソース行を維持する。alias 独自の asm シンボル・デバッグ変数は生成しない。

接続先: `internal/syntax/parser.y` / `parse.go` / `printer.go`、`internal/sema/storage_alias.go` / `hlc.go` / `program.go`。
既存の `ir.CastedValue`、`ir.UnderlyingValue`、`ir.IsPartialDef` の表現を利用し、IR の新しいアドレス表現は増やしていない。

## 8. 検証対象

- 独立した2モジュールが共通モジュールの領域を異なる struct 型で利用できる。
- O0 / O2 とも RAM の追加確保・alias 初期化コードがなく、固定フィールドが直接アクセスになる。
- 元配列・複数 alias の交互の読み書き、ループ・分岐・関数呼び出し・インライン化で値が一致する。
- `uint16`、入れ子 struct、配列フィールド、ポインタ・farfn を含む型、型を変えた符号解釈を確認する。
- struct リテラル代入の省略フィールドはゼロになり、alias の範囲外は書き換わらない。
- `&alias`、値コピー・引数・戻り値、重なる部分領域間のコピーを確認する。
- volatile の読み書きを消さず、非 volatile の別名宣言が元領域を暗黙に volatile 化しない。
- 未使用 alias も検査し、過大サイズ・循環・非公開参照・禁止対象・不完全型に診断を出す。
- public / 選択インポート / 再公開 / 前方参照 / 局所 alias の名前解決を確認する。
- 既存の識別子 `alias` と formatter の往復を壊さない。

## 9. 初版の範囲と将来拡張

実装した範囲は「V2、文脈キーワード alias、型必須、対象はグローバル領域の先頭、宣言スコープはグローバル／局所」。
O0 / O2 の実行・生成アセンブリ、モジュール間の共有、volatile、診断、構文・整形のテストを追加した。

部分領域の指定、ローカル変数への alias、readonly alias、汎用の名前別名、union は別途検討する。
固定参照先ポインタの直接アクセス化、定数 struct リテラルの即値格納は独立した最適化として扱う。

SoA コンテナとの組み合わせも初版では対象外。将来、共有バッファ内に各フィールドの配列を配置する
`soa alias` のような宣言を検討できるが、フィールド配列の配置・容量・SoA ハンドルとの接続を別途定義する必要がある。
現状でも、配列フィールドを持つ通常の struct への alias なら、手動で同様のメモリ配置を表現できる。
これは既存の SoA コンテナ／ハンドルとの連携を提供するものではない。

参考: Free Pascal の absolute 変数（[Reference guide 第4章](https://downloads.freepascal.org/fpc/docs-pdf/ref.pdf)）は
既存変数と同じ位置に別の変数名を置く先例。C/ca65 の union のように全候補型を一か所へ集める必要がない。
