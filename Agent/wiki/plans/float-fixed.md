# 浮動小数（f16 / f32）と固定小数（u8f8 など）の計画

2026-10-24 にユーザーから依頼（「浮動小数行こうか、f16, f32 の実装はできる？」「固定少数も対応したい」）。決めた経緯は
[../../discussions/2026-10-24-float-fixed.md](../../discussions/2026-10-24-float-fixed.md)。まだ実装していない（コードは読んだだけ）。

## 決めたこと（2026-10-24 ユーザー）

共通
- fc 4 だけ。リテラルは `1.5`・`2e-3`・`0.5e3`（`1..5` の範囲と `.A` の enum の省略は今のまま。`1.` の後が `.` なら整数）
- **型のない実数の定数**: 浮動小数・固定小数の相手に合わせる（`x * 2`・`x + 0.5`）。整数の相手にはエラー（黙って切らない）
- **変換は `as` だけ**: 整数 ↔ 浮動小数 ↔ 固定小数、f16 ↔ f32、分け方の違う固定小数どうし
- **出力**: `@printf` / `@format` の `{:.3}` で小数点以下の桁（四捨五入）、`{}` は既定の桁。無限大・NaN は `inf` / `-inf` / `nan`

浮動小数（f16 = IEEE 754 binary16、f32 = binary32）
- **IEEE に完全に従う**: 最近接偶数丸め・非正規化数・±0・±無限大・NaN。定数の畳み込みは Go の `float32` とビット単位で一致させる
  （f16 は Go に無いので丸めを自前で書く）
- 数学の関数は sqrt（正しく丸める）・floor / ceil / round まで（fclib に）

固定小数
- **型名は `[u|i]<整数のビット>f<小数のビット>`**（`u8f8`・`i4f4`・`i12f4`・`i16f16`）。合計 8 / 16 / 24 / 32 ビットのどの分け方も。
  中身はその大きさの整数（`u8f8` は 2 バイト、値 = 整数 / 256）
- **掛け算・割り算の結果は負の無限大へ切り捨て**（算術シフトのまま）。リテラルと浮動小数からの変換は最近接に丸める（範囲の外はエラー /
  `as` は折り返し）
- **整数と混ぜる**: `*` `/` は整数の値（変数も）をそのまま書ける（`v * 3`・`v / n`。スケールだけの計算で正確で速い）。`+` `-` 比較は型のない
  定数だけ（`v + 1` は 1.0）で、整数の変数は `as`。分け方の違う固定小数どうしも `as`
- **桁あふれは折り返す**（整数と同じ）

## 作り方の案

- **型**: `types.Kind` に `Float` と `Fixed`（Fixed は `Frac` = 小数のビット数を持つ。大きさと符号は Int と同じ）。名前は sema の
  `basicType` が `u8f8` の形を読む（fc 4 だけ）
- **固定小数は今の整数の後段にほぼ乗る**: 足し算・引き算・比較・シフト・折り返しは中身の整数の命令そのまま（同じ分け方どうし）。
  掛け算 `a * b` は「広げて掛けて小数のビット数だけ算術右シフト」、割り算は「被除数を小数のビット数だけ左にずらして広げてから割る」。
  sema で IR の整数の命令に下ろす（32 ビットの乗除算・シフトの速い形をそのまま使う。i16f16 の掛け算は 64 ビットの積が要るので
  ランタイムに 32×32→64 を足す）。整数を掛ける・割るのは中身の整数の命令そのもの
- **浮動小数はランタイムの関数を呼ぶ**（share/runtime_float.asm を使ったビルドだけリンク。今の runtime_wide と同じ形）: f32 の
  加減乗除・比較・整数との変換・f16 ↔ f32。f16 の演算は f32 に広げて計算して丸め直す（binary32 は binary16 の `+ - * /` と sqrt を
  二重に丸めても正しい精度がある）。IR には新しい命令を作らず呼び出しにする（最適化は呼び出しとして扱う）か、opt が見える命令に
  するかは段 1 で決める
- **定数の畳み込み**: 固定小数は有理数として正確に（中身の整数の計算）、f32 は Go の `float32`、f16 は自前の丸め
- **インタプリタ**: 固定小数は整数の命令なので今のまま。浮動小数の関数は Go の native（interp の `natives`）で走らせる
- **出力**: fclib/fmt.fc に固定小数（中身の整数と小数のビット数から）と浮動小数の `{:.N}`（f32 を 10 の累乗で掛けて丸めて整数にしてから
  10 進。f32 の精度の外の桁は 0）

## 進め方（案）

1. 共通の入口: 字句解析（実数のリテラル）、型のない実数の定数（sema。値は Go の big.Rat か float64 で持つ）、`as` の規則、書式の `{:.N}`
2. **固定小数**（安い・ゲームのサブピクセルにすぐ使える）: 型・規則・掛け算 / 割り算の下ろし方・出力・模型の fuzz（中身の整数の
   値を Go で計算して比べる）
3. **f32**: ランタイム（asm。IEEE の丸め・非正規化数・特別な値）・畳み込み・インタプリタ・出力・模型の fuzz（Go の float32 と比べる。
   特別な値・非正規化数・丸めの境目の値を多めに）
4. **f16**: f32 との変換と、演算の包み（f32 で計算して丸め直す）
5. fclib/math.fc に sqrt / floor / ceil / round、docs/reference/language.md に浮動小数と固定小数の節を足す

## 見積もり（実装する前の見込み。測っていない）

- f32 の足し算 150〜300 サイクル、掛け算 600〜1500、割り算 1500〜2500、ランタイム 1.5〜2.5 KB。NES の 1 フレーム（約 29780 サイクル）で
  掛け算は数十回まで
- 固定小数の足し算は中身の整数と同じ（u8f8 なら u16 の足し算）、u8f8 の掛け算は 16×16→32 ビットの掛け算と 1 バイトの移動
- 大きい順に: f32 のランタイム（正しさを fuzz で詰める）、出力の書式、固定小数の掛け算 / 割り算の下ろし方と A1 の規則との関係

## まだ決めていないこと（段 1・2 で相談）

- 浮動小数の比較で NaN（`x == x` が偽）を IEEE のとおりにするか（案: IEEE のとおり）
