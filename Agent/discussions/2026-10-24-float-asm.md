# 浮動小数のライブラリを asm に（2026-10-24）

[2026-10-24-float-games.md](2026-10-24-float-games.md) の相談（f32 を多く使うゲームが -O 0 で NROM にぎりぎり）の案 (b)。ユーザー
「-O2 でも早くなったりはしない？」→ 3〜5 倍の見込み（呼び出し・4 バイトのまま・1 ビットずつのシフト・フラグを使えない）を答え、
「では、asmに変えて。各型ごとに作らないといけない感じになる？」。型ごとには要らない（f16 は f32 に広げる、固定小数・整数は
ldexp・to_sat の引数で）ので、f32 の一式だけを asm にした。

## 決めたこと

- f32 の関数の全部と f16 との変換・to_sat を fclib/float.asm に。float.fc は宣言だけ（関数名と引数は前と同じなので sema は変えない）
- 作業域は `reg`（掛け算・割り算のランタイムと同じく呼び出しをまたいで残さない・割り込みから保護しない約束に乗る）と scratch
- 公開の関数どうしは呼ばない（docs/reference/assembly.md の frame の約束）。共通の処理は asm の中のラベル
- インタプリタには Go の float32 で同じ結果を返す natives を足した（判定を飛ばさない）
- runtime.asm の掛け算の表 `__mul_tbl_*` を export した（バイト列は変わらない）

## 結果（2026-10-24、最後の状態で測った）

- 速さ（1 回あたりのサイクル数、fc の版 → asm）: + 3397 → 1082、* 4258 → 1885、/ 4801 → 2959、@sqrt 22372 → 5729、< 530 → 341、
  u8f8 へ 2677 → 781、f16 の + 6036 → 2125
- 大きさ: 浮動小数のモジュールは -O 0 / -O 2 とも 4114 バイト（fc の版は -O 0 で 11.5〜13.2 KB）。games の -O 0 の ROM の残りは
  billiards 約 160 バイト → 8.3 KB、artillery 約 900 → 11 KB、orbit 約 3.5 KB → 11.6 KB、lander 約 5.2 KB → 9.4 KB。billiards の AUTO を
  ゴーストボールの形に戻した
- 見込み（+ 600〜900、* 1000〜1500）には届かなかった。残りは仮数の 3 ビットの丸めの印のずらし（取り出しと詰め）と、呼ぶ側の引数の
  写し。1 バイトの丸めの印にする書き直しは design/float-fixed.md の「残り」

## 分かったこと

- 書いた asm の掛け算に、部分積の繰り上がりが 2 バイトより上へ伝わらない誤りがあった（`cpy` がキャリーを変える）。TestFloatLib の
  既定の 6 本（1 本 60 式）では通り、ゲームの `unit()` の長さが 1.0022 になって気づいた。200 本なら戻すと 140 本落ちるので、既定を
  40 本にした（2 秒弱）
- 6502 の分岐は ±128 バイトなので、asm のループや遠いラベルへの分岐は「逆の分岐で飛び越えて jmp」に。ca65 のマクロの中の `.local` の
  ラベルは普通のラベルなので `@` のラベルの範囲を切る（無名のラベルを使う）
- 呼ばない関数のフレームに書いてはいけない（to_i32 の結果を to_u32 の戻り値の場所にも書きかけた。兄弟の関数のフレームは呼び出し元の
  フレームと重なりうる）
