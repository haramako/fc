# pal.fade を細かくする方法と強調ビット

## 背景

`fclib/nes/pal.fc` の `fade` は `shade` で色番号から $10 ずつ引くだけで、明るさは 4 段しかない。フェードイン/アウトをもっと細かくする方法を相談した（まだ実装はしていない）。

## 出た候補

1. PPUMASK の強調ビットを 3 つとも立てて、段の間に半段を挟む
2. 32 色を一度に変えず、色（サブパレット）ごとに段を進める時刻をずらす
3. 色ごとの表（`darker[64]` や、RGB から作った「元の色 × t に一番近い色」の表）を持つ。白や任意の色へのフェードもできる
4. 2 つの段を 1 フレームおきに出す（ちらつく）

## 強調ビットについて調べたこと（NESdev wiki、2026-10-01 に読んだ。実機・エミュレータでは確かめていない）

- 商用で使った例: Fun House（フェードアウト）、Lagrange Point（メニューとの切り替えの手軽なフェードアウト）、Super Spy Hunter（ポーズ中）など。3 つとも立てて暗くする使い方が多く、homebrew（Battle Kid など）でも画面を暗くするのに使う。輝度の段の間に挟む使い方をした例は見つけていない
- NTSC の 2C02: 3 つとも立てると、電圧（絶対値）が平均 0.816 倍になる。$xE / $xF の黒は変わらず、$xD 列（$0D / $1D の黒、$2D / $3D の灰色）は変わる
- PAL / Dendy はビット 5 と 6 が入れ替わる（3 つとも立てるなら同じ）
- RGB の PPU（2C03 / 2C04 / 2C05: PlayChoice-10、VS. System など）は、その成分を最大にする。3 つとも立てると画面が白くなる
- NESdev の電圧の値（low 0.350 / 0.518 / 0.962 / 1.550、high 1.094 / 1.506 / 1.962 / 1.962、黒 0.518）で、机の上で計算した。色つきの $3x に強調を掛けると、黒からの高さが約 0.92 になり、$2x（約 0.94）とほぼ同じになる。一番上の半段は効かない。下の段（$2x 以下）では半段がきちんと間に入る
- ついでに分かったこと: 2C02 では $20 と $30 が同じ白なので、今の `shade` で白（$30）を 1 段暗くしても見た目が変わらない

## テスト ROM で確かめた（同じ日）

`Agent/scripts/emphasis-fade-test/` に ROM を作り、MesenCE 2.2.1 の既定のパレットで段ごとの色を測った（数値は README）。

- 上の机の上の計算のとおり、$3x に強調を掛けた色は $2x より暗い（輝度 153 と 162）。9 段のフェードでは、8 → 7 → 6 で一度暗くなってから明るく戻る
- 白は 8 → 7 → 6 が 254 → 179 → 254 になる（$30 → $20 が同じ白のため）。強調を挟むと白がちらつく
- 色つきの色は、$2x 以下で半段がきちんと入る
- 強調を「一律に段の間へ挟む」形では使えない。使うなら、段ごとに色の表と強調の有無を決める（候補 3 の表と組み合わせる）
