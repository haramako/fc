# 24 / 32 ビット整数を入れる相談（2026-10-24）

## きっかけ

ユーザー「fc に 24bit 整数と、32bit 整数を入れてほしい。プランして」。前段・中間と後段・テストと fclib の 3 つに分けて、
2 バイトまでを前提にしている所をコードを読んで調べ、計画を Agent/wiki/plans/wide-int.md に書いた。

## 分かったこと

- 型の表現とデータの写し、加減算・比較などの codegen はバイト数のループで書いてあり、3・4 バイトでは一度も実行されていない
- 黙って間違える所は、符号拡張（元が 1 バイトの前提）、乗除算（ランタイムと名前・オペランドの配置が 16 ビットまで）、定数データ
- sema の規則（E / D の検査、A1 の広げ、型のない定数）は `Size <= 2` で止まり、3・4 バイトは検査されずに素通りする

## 決めたこと（ユーザーが案をそのまま選んだ）

1. fc 4 だけで使える（fc 2 / 3 の printf と暗黙の狭めが 16 ビットで切り詰めるので、旧版は触らない）
2. 型のない定数は入る一番狭い型（u24 / i24 → u32 / i32）。今の u8 → u16 の段と同じ考え。65536 以上の定数の意味が変わるのは受け入れる
3. A1 の広げは仕様どおり 3・4 バイトにも当てる（遅くなるのは、代入先を広い型にした結果として明示的）
4. 添字・ポインタの足し算・slice の長さに 3・4 バイトの値はエラー（番地は 16 ビットなので、黙って切ると気づけない）
