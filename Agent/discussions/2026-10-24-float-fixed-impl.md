# 固定小数と浮動小数の実装（2026-10-24）

[2026-10-24-float-fixed.md](2026-10-24-float-fixed.md) で決めた形で、ユーザー「実装を最後まで進めて」を受けて実装した。設計は
Agent/wiki/design/float-fixed.md。

## 実装の中で決めたこと（相談で決めていなかった細部）

- 固定小数は Kind Int のまま `Frac` を持つ型にした（別の Kind にすると後段の最適化の条件 `Kind == types.Int` から黙って外れる）。sema では
  enum と同じく整数の規則から外す（`Type.Tagged`）
- 固定小数に A1 の広げは当てない（変換は `as` だけなので、型の違う代入はエラー）。固定小数 → 整数の `as` は負の無限大へ（固定小数の
  丸めの規則に揃えた）、型のない実数の定数 → 整数は 0 へ、浮動小数 → 整数は 0 へ（C と同じ）。浮動小数 → 整数・固定小数は範囲の外を
  飽和（NaN は 0）
- 浮動小数のライブラリは計画の asm でなく fc で書いた（正しさを Go と比べて詰めやすく、インタプリタも走る）。速さは見積もりより一桁遅い
  （f32 の足し算 約 3200 サイクル）ので文書に実測を書き、速くするのは後
- NaN を作る演算の結果は 0x7fc00000 に揃える（定数の畳み込みと実行時をビットまで一致させるため）。NaN の比較は IEEE どおり
- 型のない定数が浮動小数の範囲を超えるのはエラー（`x as f16` なら無限大）。整数と同じく黙って値を変えない
- 出力の `{}` は計画の「6 桁」を C の %g と同じ決め方にした（`0.0001` は f32 では 0.0001 より少し小さいので、値で決めると `1e-04` になる）
- `var x = 1.5` は f32（Go の float64 の既定に当たるもの）

## 分かったこと

- 字句解析は int64 に入らない整数のリテラルを黙って折り返していた（前から。f32 の最大の近くの整数を書くと 0 になった）。正確な値で持つ
  ようにした
- 模型の fuzz で「わざと壊して落ちるか」を見たとき、壊し方によっては生成した値が弱くて 1 本も落ちなかった（浮動小数 → 固定小数の丸め:
  乱数のビットの値は範囲の外か小さすぎて丸めの差が出ない）。中くらいの大きさの小数の値を足して落ちるようにした。1・2 バイトの固定小数の
  掛け算の右シフトは算術でも論理でも結果が同じ（下位だけを使う）ので、その壊し方は対照にならなかった
- 対照の手順で `cp` が上書きの確認で止まり、古い控えに戻して変更を 2 つ失いかけた（気づいて当て直した）。控えは毎回新しく取り、戻ったことを
  `cmp` で確かめる
