# 固定小数・浮動小数を使うゲーム 4 本と、作って見つかったこと（2026-10-24）

ユーザー「固定少数、浮動小数をつかったサンプルのゲームも追加して」→ 案（月着陸・砲撃・ビリヤード・軌道）→「1,2,3,4 をつくって」。

## 作ったもの（games/）

どれも「毎フレームの動きは固定小数、たまの出来事の計算と結果の出力は f32」の分け方（f32 の 1 回は数千サイクル、1 フレームは約
29800 サイクル）。

- **lander**: 位置 i16f8・速さ i8f8・重力と噴射（`cos as i8f8 * THRUST / 127`）。着地の速さ `@sqrt`、点数の合計と最良を f32 で `{:.1}`
- **artillery**: 撃つ時の初速を f32 のテイラー展開の sin / cos で、外れた距離 `@sqrt`、狙い直しは割線法 (f32 の割り算)。弾は i16f8・
  i8f8 で風と重力
- **billiards**: 玉は struct (`x:i12f12`・`vx:i4f12`)、摩擦は固定小数の掛け算。衝突の法線は f32 の `@sqrt` と割り算（衝突の
  フレームは数フレームに延びる）
- **orbit**: 船は i16f16。重力 GM / r² は f32 の計算を 4 フレームに分け（2 乗の和 → `@sqrt` → 加速度 → 8 フレームに 1 回の軌道の
  要素: 近点・遠点）、AUTO は近点のあたりで遠点を、遠点のあたりで近点を目標に寄せる噴射

テスト: `internal/nes/games_test.go` の TestGameLander / Artillery / Billiards / Orbit と TestGamesSameAtTick の 4 行。CHR に
LANDER・TANK・FLAME・PIP・PROBE を足した。

## 見つけて直したコンパイラの不具合（どれも回帰テストあり。戻すと落ちることを確かめた）

1. **整数の式の `as f32` / `as 固定小数` が A1 の内部エラー**（`(tank_x(t) + 8) as f32`: 「computed in u8 but is used as u32」）。
   整数の `as` と同じく、自分の型で計算した値を変換するようにした（`explicitCast`。符号の混ざった式は整数と同じエラー。前は固定小数へは
   黙って通っていた）
2. **グローバル変数・配列・struct のフィールドの型のない実数の定数を型に合わせていなかった**: `var q:u4f4 = 15.5;` は asm が壊れ
   （`.LOBYTE()`）、`const T:[3]u8f8 = [0.5, 1.5, 2]` は「untyped float と u8」、`P{x: 1.5}` は codegen の panic。`var g = 1.5;`
   （グローバル）は f32
3. **型のない実数の定数の名前 `const K = 0.75;` が asm に値の無い `_m_K =` を書いた**（codegen が書かない）
4. **引数の式が下ろすとライブラリの呼び出しになる形（浮動小数の演算・`as`、3・4 バイトの固定小数の `*` `/`）で、-O 0 で積み始めた
   引数が壊れる**。`containsCallAny` が構文の呼び出しだけを見ていたので「呼び出しなし」として評価しながら積み、後の引数の変換が呼ぶ
   `from_mag` の静的フレーム（呼び先の `unit` と兄弟なので重なる）が 1 つ目の引数を壊した。billiards が -O 0 と -O 2 で違うことを
   TestGamesSameAtTick が見つけた（手数 34 の最初の衝突。-O 2 の値が手計算と合った）。i16f16 の掛け算を引数に書く形は固定小数を
   入れた 5eed801 からの不具合。型を見て下ろすと呼び出しになる式も数える `lowersToCall` にした

## ライブラリの変更

- 浮動小数 → 整数・固定小数の `as` を float.fc の `to_sat_i` / `to_sat_u` の 1 回の呼び出しに（前は呼ぶ所に ldexp32 → rint32 → to_i32
  と飽和の比較を出していた）。1 つにまとめた `to_sat` は -O 0 で大きくなったので符号で分けた（使う方だけリンクされる）
- 小さくした: `round_int`（|x| < 1 を同じ式に）、比較を `cmp32` に、fmt の `f32`（固定の形と指数の形の桁を並べる所を共有）

## 生成器の穴（直した）

- 浮動小数 → 小さい型（i8〜u16f16）への `as` が無く（`i32` と `i16f16` だけ）、負の側の飽和を壊しても 0 本だった → 14 の型を足した
  （壊すと 130 本）
- 葉が全部 `id_f32(リテラル)` の呼び出しで、引数の式がいつも「呼び出しを含む」になっていた → グローバル変数の葉（初期値の経路も
  通る。2. を戻すと 202 本落ちる）と引数 3 つの `pick3` を足した。ただし 4. は静的フレームがたまたま重なる置き方でしか出ないので、
  模型の fuzz では見つからない（`floating_args.fc` が見張る）

## 相談したいこと

- **f32 を多く使うゲームは -O 0 で NROM の 32 KB にぎりぎり**（-O 0 の残り: billiards 約 160 バイト、artillery 約 900、orbit 約 3.5 KB、
  lander 約 5.2 KB。2026-10-24 の最後の状態で .map から）。float.fc は -O 0 で 11〜13 KB（-O 2 で約 10 KB）、-O 0 の f32 の演算は
  呼ぶ所で 1 回 約 30 命令。バンクのあるマッパーでも固定の所は 16 KB で、float と fmt のライブラリが入らない。billiards は AUTO の
  ゴーストボール（f32 の単位ベクトルを 2 回）を外し、色の玉の中心を狙う形にして収めた。案: (a) 標準ライブラリのモジュールは -O 0 でも
  最適化する（pipeline は関数ごとに最適化しているので作れそう。fclib を -O 0 で確かめる層が減る）、(b) float.fc の主な関数を asm に、
  (c) そのまま（ゲーム側で詰める）
- `@min` / `@max` / `@clamp` が浮動小数に使えない（整数と固定小数は使える。docs に書いた）。NaN の扱いを決めれば足せる
