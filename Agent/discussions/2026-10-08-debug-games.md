# fc のデバッグを兼ねた小さなゲームと共通の CHR（2026-10-08）

## 背景

fc のデバッグを兼ねて小さなゲームをたくさん作る。そのために、共通で使う CHR を 1 つ作る（BG とスプライト、8×8 と 16×16 を
混ぜた汎用のもの）。

## 決めたこと

- 置き場所は `examples/` と別の `games/`（`games/common/` に共通の CHR、`games/<名前>/` にゲーム 1 本ずつ）
- CHR の元はテキストのドット絵 `games/common/tiles.txt`。`tools/chrgen` が `tiles.chr`（8 KB）・`tiles.fc`（名前の定数と
  oam.meta の表）・`tiles.png`（確かめ用）を作る。内蔵のフォント（`fclib/nes/font.txt` → `font.chr`）と同じ考え方
  （エージェントが直接書けて差分が読める。生成物が合っているかは `go test ./tools/chrgen` が見る）
- 配置: BG は $0000（$20〜$7F が ASCII の文字。`@printf` の文字のままタイルの番号になる。テキストアドベンチャーのために
  小文字まで）、スプライトは $1000
- スプライトは 8×8 のモードと 8×16 のモードを混ぜて使う: 列ごとに上下 2 枚を続けて置く（16×16 は左上・左下・右上・右下、
  8×16 は上・下、8×8 は絵と空白）。8×16 のモードはタイルの番号の下位 1 ビットが $1000 を選ぶので、`NAME_T16`（= n | 1）と
  `NAME_M16` の表で使う
- 絵は素朴でよい。色の番号の約束は 0 透明・1 輪郭（暗い）・2 本体・3 ハイライト（パレットを替えて色違いにする）

## ゲームの候補（12 本）

ユーザーの追加の希望: ローグライク・テキストアドベンチャー（英語）・ワイヤーフレームの宇宙船シューティング。

| # | ゲーム | 主に通す fc / fclib の機能 |
|---|---|---|
| 1 | ブロック崩し | 8×8 のスプライト、BG のブロックの書き換え、固定小数点の速さ、当たり判定 |
| 2 | ドットイートの迷路 | 迷路の壁のタイル、敵の追いかけ（soa の interface で敵ごとの動き）、16×16 のスプライト |
| 3 | インベーダー | 8×16 のモード、たくさんのスプライト（soa）、行ごとの動き |
| 4 | 縦シューティング | interface のタスク（敵・弾・爆発）、8×16 のモード、乱数 |
| 5 | 横スクロールのジャンプアクション | 2 画面のスクロール、16×16 のメタタイル・属性、重力 |
| 6 | スネーク | BG だけ、リングバッファ |
| 7 | 倉庫番 | 16×16 のメタタイル、面のデータ、やり直し（スタック） |
| 8 | 落ちものパズル | BG の 8×8 の箱、回転の表、行を消す |
| 9 | マインスイーパー | 塗りつぶし（再帰か自前のスタック）、乱数 |
| 10 | ローグライク | ダンジョンの生成、ターン、interface（敵・アイテム）、窓の枠と文字 |
| 11 | テキストアドベンチャー（英語） | 文字列・単語の切り出しと照合（str）、`@format`、状態の表 |
| 12 | ワイヤーフレームの宇宙船シューティング | CHR RAM に線を描く（ビットマップ）、3D の回転（sin / cos・固定小数点）、vblank の転送の量 |

## fclib の足りなそうな所（作る前の見込み。作りながら確かめて、別の記録で相談する）

- `oam.meta` の上下の反転は 8×8 のスプライトの前提（`dy = -dy - 8`）で、8×16 のモードでは位置がずれる。パレットも表の attr に
  固定（呼ぶときに替えられない）
- 16×16 のメタタイルを書く（2×2 のタイルと属性の 2 ビット）関数が無い（`vram.set_attr` は属性のバイトの写しを呼ぶ側が持つ）
- CHR RAM（fc.toml の `chr = 0`）に絵を書く・線を描く仕組みが無い（ワイヤーフレームに要る。vblank に送れる量の工夫も）
- 文字の窓（枠・折り返し・1 文字ずつ出す）
- fclib に入れるか、`games/common/` の追加のライブラリにするかは、作ってから決める
