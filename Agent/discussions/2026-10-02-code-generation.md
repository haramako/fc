# コード生成（C# の Source Generator・go generate のようなもの）

2026-10-02。外部コマンドの定数マクロ（`[macro_server.*]`）を広げて、コードを生成できるかの相談。

## 検討した形

1. go generate 型: ビルドの前にツールで .fc を書き出して use する。今でも fcc の変更なしにできる（fcc 側で足せるのは
   `fcc generate` 程度で、make が要らなくなるくらいの効き目）
2. 生成したモジュールを use する: `use gen/x;` で fcc がサーバーにモジュールの中身を頼み、`.fc-build/gen/` に書いて普通の
   モジュールとして読む（Program.FS / Overlay があるので足しやすい。エラーの位置も生成物のファイルを指せる）
3. 式・文をその場で展開する: 応答に種類（expr / stmts）を付け、構文解析の入口を増やす。エラーの位置の対応と名前の衝突（fc に
   衛生の仕組みが無い）が重い
- C# の Source Generator の強みは型の情報を見て生成すること。fc でやるなら、指定した型の宣言（struct のフィールド・enum の値）を
  JSON でサーバーに渡し、出力は新しいモジュールに限る（2 の延長）

## 決定

- **しばらくは普通のコード生成（ツールで .fc を書き出す）でよい**。fcc に仕組みは足さない
- やるなら、fc 側の型や宣言を解釈したうえで生成できる仕組み（上の 2 + 型の情報を渡す）にする。単に make が要らなくなる程度の
  go generate 型は作らない
