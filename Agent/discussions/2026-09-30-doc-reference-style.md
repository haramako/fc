# 文書への参照の書き方（§ の番号をやめる）

日付: 2026-09-30

## 背景

`Agent/` の整理を見直したとき、コードのコメントから文書の節を `§` の番号で指す参照が多く（`plans/v4-stdlib.md §7` など）、
番号がずれても気づけないことが分かった。`internal/codegen/call.go` の `regalloc.md §4` は、実際には §3 の中の「X の開放（§4）」の
段落を指していた。また `plans/`（済めば消える）への参照が約 70、`discussions/2026-09-20-v3-plan.md`（更新されない）を仕様として
指す参照が約 40 あった。

## 決定事項

- `§` の番号は、無くても分かるなら書かない。短い記事はファイル名だけ、長い文書はファイル名と見出しの言葉
- コードのコメントから指すのは、実装済みの仕様を書いた `wiki/design/` か `docs/` の言語仕様。`plans/` と `discussions/` は新しく指さない
- 今ある `§` の参照は一括では直さず、触ったときに直す。計画の項目を `design/` へ移すとき、新しい言語仕様ができたときに付け替える
- 規則は `Agent/wiki/AGENTS.md` の「参照の書き方」「コードから指す先」。参照が実在するファイルと見出しを指しているかの検査は、
  ドキュメントの例の検査（`plans/user-docs.md`）と同じテストに入れる予定
