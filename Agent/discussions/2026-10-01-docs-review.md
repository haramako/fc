# docs の事実関係と構成のレビュー

## 依頼と範囲

利用者から docs の記述が実装と合うか、構成に問題がないかの確認を依頼された。公開対象の手書きページ、生成する標準ライブラリの説明、サイト設定と検査経路を確認した。今回はレビューであり、利用者向け本文・実装は変更していない。

## 主な指摘

- `docs/reference/language.md` のアセンブリ節に、同じモジュールの abi frame の asm 関数どうしを呼んではいけない制約がない。`internal/frames/frames.go` の markAsmSym はこの呼び出しを区別できず、フレームを重ねうる。非公開の旧 `docs/language_reference.md` には制約が残っている。
- 「グローバル変数は 0 で始まる」は配置による例外が抜けている。`share/runtime.asm` が初期化するのは $0000〜$07FF。カートリッジ RAM の変数や address 指定の I/O にまで一般化できない。
- 生成する math.subpixel の説明は「16 フレームで v / 16 ピクセル」だが、正しくは 16 フレームの合計が v ピクセル（1 フレーム平均 v / 16）。修正元は `fclib/math.fc` のコメント。
- 生成する fmt.str_z_in の説明に「文字列で初期化した配列は終端の 0 を含む」と残っている。fc 4 では自動付加しない。修正元は `fclib/fmt.fc` のコメント。
- 言語仕様冒頭の「サイトのビルドのたびにコンパイルして動かす」は実際の検査経路と異なる。npm build / docs.yml は生成と VitePress ビルドだけ。doccheck は別の Go テストで、印のない断片は構文と書式だけを調べる。

## 構成の評価

- 導入 → emu → NES → 小さなゲーム → プロジェクト → エディタの導線は自然。
- 言語仕様の後半に ABI・静的フレームなどの上級者向け説明が集中する。基礎仕様と実機向けの応用を分け、相互リンクすると探しやすい。
- サンプル集の画面撮影手順はサイト保守の内容であり、利用者向けのサンプル紹介から移す候補。
- 旧仕様はサイト非公開だが、上記 ABI 制約やコード内参照が残るため、削除前に必要な仕様と参照を移す必要がある。

検査方法と実行で確かめた値は `Agent/wiki/docs-site.md` に記録した。

## レビュー後の修正

同日、利用者からこの方針での修正を依頼された。
誤記と初期化の例外を修正し、ABI・バンク・メモリを `docs/reference/assembly.md`・`banks.md`・`memory.md` に分けた。
旧仕様にあった ABI の制約と独自文字表・翻訳の説明を現行仕様へ移し、README・コードのコメント・リリース同梱設定の参照を更新して旧仕様を削除した。
画面撮影手順はサンプル集から外し、既存の保守手順（docs の規約と wiki）に集約した。
