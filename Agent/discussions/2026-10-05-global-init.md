# グローバル変数の初期値と、宣言・データの制限（2026-10-05）

## 背景

roadmap の「言語: 宣言・データ」の残り（struct リテラル・const の表の制限、グローバル変数の初期値）を、ユーザーが進めるよう指示した。
グローバル変数の初期値は 2026-09-26 に「まだやらない」と決めていたもので、今回の指示で実装した。

## 決定事項

### グローバル変数の初期値（fc 4 だけ）

- `var g:T = 定数;` をモジュールの変数に書ける。初期値は const の表と同じ規則の定数（整数・配列・struct・文字列・名前付きの const、
  関数・配列定数・グローバル変数のアドレス）。fc 3 までのモジュールは今までどおりエラー（0 で始まる）
- **起動のときに `main` の前に写す**（0 クリアの後）。リセットのたびに写す
- **リンカ設定は変えない**: ld65 の `load = ROM, run = RAM` の DATA セグメントにすると、fc が書く 3 種類の ld65.cfg に加えて、
  自前のリンカ設定（`@(linker_config:)`）・自前の土台のプロジェクトも直す必要がある。代わりに各モジュールが自分の記録
  `__fc_init_<mod>`（`.byte 長さ / .word 書き先 / 中身`、長さ 0 で終わる）を **FC_RUNTIME**（固定のバンク。runtime.asm が既に使う
  ので、どのリンカ設定にもある）に置き、driver が記録の番地の表 `_fc_init.s`（`__fc_init_table`）を書く
- **初期値の無いプログラムは何も変わらない**: runtime.asm の `fc_global_init` は `.ifdef FC_GLOBAL_INIT` で囲み、初期値のある変数が
  あるビルドだけ `-D FC_GLOBAL_INIT=1` でアセンブルする（ROM の golden・examples は変わらない）。写す処理は約 80 バイト
- `$0000`〜`$07FF`（既定の BSS）の変数は 0 のバイトを写さない（3 バイト以下の 0 の並びは記録を分けるより写すほうが短いので含める）。
  ほかのセグメント（カートリッジ RAM・ZEROPAGE など）は全部写す
- `@(address:)` の変数（I/O）はエラー。切り替えのバンクのモジュールの変数も、記録が固定のバンクにあるので写せる
- 確かめ: `internal/driver/globalinit_test.go`（emu -O 0 / -O 2、UxROM の切り替えのバンク、エラー）、fuzz の TestRandomProgramsV4 /
  TestRandomV3ProgramsV4 は偶数の種で main の先頭の定数の代入を宣言の初期値に移して比べる（`v4GlobalInits`。600 本で通った）

### 宣言・データの制限を外したもの

- 呼び出しの引数に型名を省いた struct リテラル（文法の `arg_list` を `lit_elem` に）。`mod.Point{…}` は `mod . (Point{…})` と読まれる
  ので `syntax.binary` が struct リテラルにする（文法の衝突は 0 のまま）。`var s = {1, 2}` は型を書くよう案内
- 名前付きの const の struct・配列を別の const の表の要素・フィールドに（中身を写す）。定数でない要素の診断はその要素の位置
- グローバル変数のアドレス（定数の添字の要素・フィールドも）を const の表・ポインタの const に。`ir.Value.SymOffset` で `sym+N`
  （データ・`.LOBYTE` / `.HIBYTE`・equ・インタプリタが足す）
- const の宣言の中で、定数の表の整数の要素・フィールドは定数（`MONS[1].hp`）
- 2 次元配列の行・ポインタの先の配列のフィールドは、値の文脈（型の無い var・配列への代入・初期化・引数）で行の写し。
  `var c:[2]u8 = a[1]` がポインタの 2 バイトを写していた誤り（黙って誤った値）もこれで直った
