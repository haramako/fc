# 既知のバグと生成器: 避ける＋「まだ再現する」ことを見張る

日付: 2026-10-19

## きっかけ

既知のバグを生成器でどう扱うかで、2 つの記録が食い違っていた。

- root の `AGENTS.md` の検証の約束（2026-10-18）: 「直るまで生成しないか Skip にしてからコミットする」
- [2026-10-18 の A1 の根本の対策](2026-10-18-a1-root-fix.md): 「既知のバグは生成器を狭めて避けない。Issue に紐づけた既知の
  失敗として扱う」（`TestRandomArithV4` が `@min` に 8 ビットの引数を作らない回避が、バグを見えなくしていたため）

後者の「既知の失敗として扱う」仕組みは無く、そのままでは毎晩の fuzz が赤くなる。F6 の誤検出は今も生成器で避けている（`arMarkTy`）。

## 検討した案

- A 避ける: 毎晩は緑。直っても回避を外し忘れる
- B 既知の失敗として Skip（エラー文などで見分ける）: 値が違うだけの失敗は既知か新しいか見分けられず、新しいバグも飛ばしうる
- C 赤のまま: 毎晩赤いのが普通になり、新しい失敗に気づけない
- D 避ける＋「まだ再現する」ことを見るテスト: 直るとそのテストが落ちて、回避を外すよう知らせる

## 決定

- **D**（ユーザー）。既知のバグの最小の再現を `internal/driver/known_bugs_test.go` に「再現する」ことを期待するテストとして置き、
  生成器の回避はそのテストと Issue から指す。root の `AGENTS.md` の約束をこれに直した。2026-10-18 の A1 の記録の「狭めて避けない」は
  これで置き換える
- 最初の 1 つは `TestKnownBugF6FalseError`（`Agent/issues/local-2026-10-18-mixed-sign-false-error.md`）
