# 2 次元の配列のループの最適化（強さの低減）（2026-10-08）

## きっかけ

games/blocks の AUTO の思考が 1 手に約 8 フレームかかっていた（スクショで NEXT が空に見えた件の調べ）。生成コードを見ると
`board[y][x]` を y で回すループで、行の番地 `y * 10` を毎周作り直して間接で読んでいた（1 マス約 50 サイクル）。
ユーザーに「ループで掛け算を足し算に置き換える最適化（強さの低減）」を説明し、進めることになった（「ok, 進めて」）。

## 決めたこと

- 3 段に分けた: 2 次元の添字を 1 バイトの添字に（fieldindex を広げる。配列全体が 256 バイト以内なら範囲内の添字は折り返さない）、
  ループ不変の計算をループの前へ（licm。今まで無かった）、強さの低減（strength）。詳細は Agent/wiki/design/ssa.md §12
- 強さの低減は **毎周の命令が増えないときだけ** する（2 のべきでない定数の掛け算か、その命令が誘導変数の唯一の使用）。
  全部置き換えると grid のベンチが licm だけのときより遅くなった（測って確かめた）
- 効果を追うために bench に `grid` を足した（答えは Python で照合）。3,117,411 → 1,860,921（−40.3%）、bgdecode −4.3%、
  castle の 1 フレームは変わらず（ROM の golden は変わる。最適化のコミットでいつも更新している扱いのまま）
- fuzz に `TestRandomGridV4`（期待値は Go で計算）、bugzoo に strength-mul-step・licm-loop-def・index2d-const-row を足した

## 残した候補

- 上下左右を数える形（`m[y-1][x] + m[y+1][x] + …`）を 1 つの添字と定数のずれにまとめる（添字 y * 16 + x が 0〜255 に収まることを
  支配する比較から示す必要がある）
