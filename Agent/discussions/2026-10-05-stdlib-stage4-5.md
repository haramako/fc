# 標準ライブラリの段 4・5 の残り

2026-10-05。ユーザーの依頼「標準ライブラリの拡充（v4-stdlib.md §7 の段 4・5）を進めて」。§3 の案のモジュール・関数と今の fclib を
突き合わせると、残っていたのは lzw の slice の版と「古い fclib を消す」だけだった（ほかの §3 の API・メタタイル・属性・フェード・
音の呼び出し口・マッパーは 2026-09-29 までに入っていた）。

## 決定

- **lzw を slice で受け取る形にする**: `lzw.unpack(dst:[:u16]u8, src:[:u16]const u8):u16`（足りなければ止まる）と `try_unpack`
  （失敗なら 0xffff）。lz4・rle と同じ形。作業域はフレーム（`@(scratch: 11)`）に移し、固定のゼロページ $7C〜$7E を使わない。
  書き先の長さ・一致の距離（0 か書き先の頭より前）・一致の長さ・入力の終わりを確かめる（入力の終わりはビットを読む下請けの中で
  調べ、入口のスタックの高さに戻して失敗を返す）。`read_bit` / `read_vln` / `read_vln16` は公開しない（asm の中の下請け）
- 旧版は「同じ名前のモジュールの入れ替え」（2026-09-29 決定）どおり castle の src と test/ の横にコピー（castle の ROM・test_lzw の
  golden は変わらない）
- **LZW の圧縮は fc に入れない**（`@lzw` は作らない）。新しいデータには lz4 を使う。テストの圧縮は Go のテストの中だけ（`lzwPack`）
- **fc 3 の `stdio`（emu / nes）と `unittest` は消さない**: fc 3 以前のソース（test/、bench/、fuzz の種、migrate の前のコード）と、
  fc 3 の `printf` などの組み込みが使う。fc 3 の読み込みをやめるときに一緒に消す
- castle を新しい API に移すのは §8 の 12 の決定どおり後で
