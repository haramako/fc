# 浮動小数と固定小数の相談（2026-10-24）

## きっかけ

24 / 32 ビットの整数を入れた後、ユーザー「次は浮動小数行こうか、f16, f32 の実装はできる？」。続けて「固定少数も対応したいのだけど、
それも併せて検討して」。計画は Agent/wiki/plans/float-fixed.md。

## 調べたこと（2026-10-24、Web で）

- cc65: リリースされた版に浮動小数は無い。IEEE 754 の 32 ビットの PR #1777 は 2022 年から下書きのまま（2025-06）。保守者から NaN・INF の
  検査がほとんどの関数に入るので IEEE をやめて簡単な形式にする案が出ていた
- llvm-mos: 浮動小数の Issue #10 は 2023-12 に完了。ホームページは IEEE-754 の浮動小数を持つと書く（中身は確かめられず）
- Oscar64: float はあるが「No NaN support for floats」
- SDCC: IEEE の単精度、関数は gcc の floatlib.c から（2005 年のマニュアル）
- z88dk（Z80）: math32 / math16（半精度）とも「mostly compliant with IEEE-754」。math16 は 32 ビットの 2〜3 倍速い
- Microsoft BASIC（6502）: IEEE でない 40 ビット（約 9 桁）

## 決めたこと

- 浮動小数は **IEEE に完全に従う**（最近接偶数丸め・非正規化数・±無限大・NaN）。理由: Go の float32 とビット単位で一致するので、
  定数の畳み込み・実行時・模型の 3 つを比べる今の検証の形がそのまま使える（ユーザーは利点・欠点・他の処理系の比較を見て選んだ）
- 整数・浮動小数・固定小数の変換は `as` だけ。出力は `{:.3}` のように小数点以下の桁を指定。数学の関数は sqrt / floor まで
- 固定小数の型は `u8f8` の形（合計 8 / 16 / 24 / 32 ビットのどの分け方も）、掛け算・割り算は負の無限大へ切り捨て、`*` `/` だけ
  整数の値をそのまま書ける（`+` `-` 比較は型のない定数だけ）、桁あふれは折り返す
