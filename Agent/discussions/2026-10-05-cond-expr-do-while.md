# 条件式 `c ? a : b` と do-while（2026-10-05）

## 背景

ロードマップの「言語: 整数と式」の条件式と、「制御構文」の do-while（2026-09-26 に「やること候補（すぐではない）」）を、
ユーザーの依頼で fc 4 に入れた。

## 決めたこと

- **fc 4 だけ**の構文にする。fc 3 以前のソースの `?:` は「fc 4 syntax」のエラー。`do` は fc 4 の予約語で、fc 3 のソースでは
  名前のまま（fc 3 → 4 の migrate が `do` を `do_` にする。asm からの参照 `_mod_do` は直さない）。fc 2 / 3 は移行用の版なので
  新しい構文は足さない
- 優先順位は `||` の下、代入の上で、右から結び付く（C と同じ）
- **条件式の型**（sema/cond.go の condJoin）:
  - 型付きどうしは二項演算と同じ互換型（大きいほう、同じ大きさなら符号付き）。合わなければエラー
  - 片方が型のない定数なら比較と同じ規則で相手に合わせる（`c ? x : 200`（x:i8）はエラー。比較の規則なのは、黙って切り詰めると
    値が変わるため）。ただし文脈の型（代入先・引数・戻り値・比較の相手。withExpected）に両方が入るならその型
    （`g = c ? -2 : x`（g:i16、x:u8）は通す。最初の実装はエラーにしていて、テストを書いて不便と分かった）
  - 両方とも型のない定数なら文脈の整数型（入らなければエラー: `var y:u8 = c ? -1 : 2`）、文脈が無ければ両方が入る一番小さい整数型
    （`(c ? 250 : 0) + 10` は u8 で計算して 4。変数の u8 と同じ）
  - 文脈の型は両方の枝に渡す（`.A`・null・型名を省いた struct・slice）
- **A1 では区切りにならない**（括弧と同じ）: 上から来た幅と条件式の型の大きさの広いほうで両方の枝を計算する。そのため
  `return c ? a + b : 1000`（u16）は a + b を 16 ビットで計算し、`if (c) return a + b; else return 1000;` と同じ値になる。
  枝の符号も枝ごとに広がる（i8 は符号を広げ、u8 は 0 で広がる）ので、「枝ごとに代入する」書き方と値が同じ
- **評価**: 条件を分岐にして選ばれたほうだけを評価する。条件が定数なら選ばれたほうだけをコンパイルし、条件と両方の値が整数の
  定数なら定数に畳む（const にも書ける）。条件の文脈（`if (c ? a : b)`）は値を作らずに枝ごとに分岐する
- **生成コード**: 一時変数に集めて合流で写すと `sta t / lda t / sta x` が残る（合流する一時変数は 2 か所で定義されるので A に
  載らず、写しの除去も効かない）。`return c ? …`・`x = c ? …`・`*p = c ? …` は枝ごとに return / 代入を出す（cond.go の
  condReturn / condAssign）。`var x = c ? …` の初期化は一時変数のまま（宣言の処理が評価の後に変数を作るため。型を決める段の
  整理の後に）
- **do-while**: `begin: 本体; cont: if (条件) goto begin; end:`。continue は条件の判定へ（ラベルは continue があるときだけ）。
  本体はスコープを作る（本体の宣言は条件から見えない: C と同じ）。return 忘れの検査では、抜ける break が無く、条件が `true` か
  本体が終端文（continue で条件へ飛ばない）なら終端文
