## #4 oam.meta のベンチマークと判断

emu で測った（oam.fc を frame に頼らない写しにして同じ中身を、16×16 = 8×8 の 4 枚を 14 体 × 10 フレーム）:

| 形 | 1 体あたり | 14 体 |
|---|---|---|
| `oam.meta` | 1524 サイクル | 21336（1 フレーム 約 29800 の 72 %） |
| `oam.meta`（左右反転） | 1608 | 22516 |
| games/common の `gfx.spr16`（`oam.spr` を 4 回） | 599 | 8393 |
| 利用側の `s16`（右端の列だけ省く） | 476 | 6672 |
| `oam.spr` 1 枚 | 111 | |
| 試作: 反転の判定をループの外・範囲を上位のバイトで | 1379 | |

- 報告（14 体で処理落ち）は数字と合う。`oam.meta` は 1 枚に約 380 サイクルで、`spr` の 111 を除いた残りの大半は判定でなく、汎用の
  ループの slice 越しの読み出しと i16 の計算（判定を軽くしても 1 割）
- 判断: **ライブラリで直す価値が高い**。メタスプライトはどのゲームも使い、1 フレームの半分以上を食うのは「本格的なら書き下ろす」で
  済ませる量ではない。fc のまま詰めても 1〜2 割なので、`oam.meta`（と `oam.spr`）を asm に（fclib の NES の描画は既に asm にしている:
  2026-10-05-nes-asm.md）。見込みは 1 枚 60〜80 サイクル（1 体 300 前後。見積もりで未測定）で、そうなれば 16×16 専用の関数は
  要らない（利用側の s16 の 476 より速い）。16×16 専用の速い関数は asm の meta を測ってからでよい
