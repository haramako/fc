# 8 ビットの式と型のない定数の比較は変数と同じ規則（31ef042 の模型の規則を戻す）

日付: 2026-10-19

## 見つかったこと

差分 fuzz の `TestRandomArithV4`（seed 61340040）で `((-88) << 1) != (id_u8(137) << 4)` が「-176 does not fit in u16」に
なった。調べると、比較の相手が**変数か 8 ビットの式か**で規則が変わっていた（`x:u8 = 137`、`x:i8 = 127 / -1`）:

| 式 | 変更前 |
|---|---|
| `x != -176`（x:u8） | 通る（i16 で比べる） |
| `(x << 4) != -176` | エラー（-176 does not fit in u16） |
| `x == 37440`（x:i8） | 通る（u16 で比べる） |
| `(x + 0) == 37440` | エラー（37440 does not fit in i16） |

A1 で 8 ビットの式を 16 ビットに広げたあと、型のない定数を**広げた型**（i16 / u16）で合わせていた（`planCompare` が
`wideInfo` を `adaptLit` に渡していた）。F6 の誤検出（`../issues/local-2026-10-18-mixed-sign-false-error.md`）と同じ根っこ。

## 決めたこと

- 型のない定数を合わせる規則は相手の**広げる前の型**で決める（変数と同じ）。比べる型も広げる前の型で決めて幅だけ広げ、
  広げた項は比べる型として読む（i16 に広げた項と u16 の定数を同じ大きさの符号付きで比べると 65535 を -1 と読む）
- 符号付きの相手と 32768 以上の定数は **u16 で比べる**（エラーにしない）。もとの設計の規則で、`TestConstFoldCases` の
  `(65533 > ((-81 as i8) >> 9))`（「型のない定数が i16 を超える: u16 で比べる」）が書いている
- 他のホストの 31ef042 は模型を「符号付きの相手と 32768 以上の定数はエラー」にしていたが、これは食い違っていた側
  （8 ビットの式）のコンパイラの挙動に合わせたもの（例の `x == 37440`（x:i8）は変数なら通っていた）。模型をその前の規則に
  戻した。途中でコンパイラ側を「エラーにする」に揃える案も試したが、`TestConstFoldCases`（16 ビットを超える定数の比較）が
  落ちて元の設計と合わないので採らなかった
- 回帰テスト `TestCompareWidenedConst`、bugzoo `compare-widened-const`
