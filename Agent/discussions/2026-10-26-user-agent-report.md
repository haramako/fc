# fc を使うエージェントからの報告（2026-10-26）

ユーザーが、fc でゲームを作っているエージェントの報告を貼って「確認して」。報告は 3 件 + 制約ではまったもの。

## 1. @printf の fmt が固定の所に入り、`if (false)` でも消えない

- fmt（と console・sys）は `@(bank: -1)`（固定の所）で、どのバンクからも呼べるようにするための設計。呼ぶ側のバンクへ
  追随させると、別のバンク（同じスロット）から呼んだときに呼ぶ側の文字列が読めなくなるので、追随はさせない
- **消えないのはコンパイラの穴だった**: 使われない関数の判定（`frames.Analyze`）が関数ごとの最適化より前なので、定数で消える
  分岐の中の呼び出しも辺に数えていた。再現（MMC3、`@(bank: "debug")` のモジュールに `if (CONSOLE) { @printf(…) }`、
  `const CONSOLE = false`）で、dbg の本体は 5 バイトなのに fmt 614 + console 409 + sys 57 バイトが固定の所に入った
- 直した: 最適化の後に `frames.Prune` で決め直す（直接の呼び出しは最適化の後の命令から、間接・インラインアセンブラの辺と根は
  Analyze のまま。Unused は付けるだけで外さない。呼び出し規約・フレームの配置の辺は多めのまま）。-O 1 以上だけ。
  再現で fmt・console・sys が ROM から消えた。`TestUnusedAfterOptimize`（Prune を外すと落ちる）
- guard しないで使うなら固定の所に約 1 KB が要る。固定の所が足りないなら、デバッグの出力の方式を考えてもらう

## 2. `fcc run -t nes` が 3600 フレームで落ちる

- 仕様どおり（`docs/reference/targets.md`: console.exit まで走らせ、1 分で終わらなければエラー）。CLI にフレーム数の指定は無い。
  内蔵の NES のランナーは `Screenshot`（背景とスプライト）を持つので、`--frames N` と画面の PNG を出すオプションは足せる（未着手、要望しだい）

## 3. frame.wait() だけのループが 900 フレームで 864 回

- fc 側は 1 対 1 だった（内蔵の NES のランナーで、`frame.wait(); ticks += 1;` のループが 900 フレームで 894 回、`frame.count` 895。
  差は起動と frame.init の分）。ループの中に待つもの（`vram` のキューが満杯のときの `frame.flush`、`frame.render` など）があると
  そのたびに 1 フレーム飛ぶ（`render_on` をループに入れると 447 回）。相手の 36 フレームの差は、`frame.count` の増え方と比べて切り分けてもらう

## 制約ではまったもの

- `f32 as i8` は v0.0.4 で通る（`-3.75 as i8` は -3。0 の向きに切り捨て）。相手の版か書き方を確かめる
- ローカル変数は 0 で初期化しない（設計。スカラーは読む前に代入しないと警告。struct・配列・アドレスを取った変数は警告の外）
