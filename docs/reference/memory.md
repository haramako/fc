# メモリ配置

NES の RAM の使い方と、関数の変数を置く場所。宣言の書き方は[言語仕様](./language#宣言)、領域を追加する設定は [fc.toml](./fc-toml#ram-名前)を参照。

## NES の RAM

fc が生成する土台の既定の配置は次のとおり。

| 番地 | 使い道 |
|---|---|
| `$00`〜`$6F` | fc の作業域と、関数の変数を置く領域のうちゼロページに置く分 |
| `$70`〜`$7F` | `@(segment: "ZEROPAGE")` を付けた変数 |
| `$80`〜`$FF` | fc のスタック（再帰する関数など） |
| `$0100`〜`$01FF` | 6502 のスタック |
| `$0200`〜`$06FF` | グローバル変数と、関数の変数を置く領域のうち RAM に置く分 |
| `$0700`〜`$07FF` | スプライトの `oam`（既定）または fc.toml の `[ram.*]` |
| `$6000`〜`$7FFF` | カートリッジの RAM（搭載している場合。fc.toml の `[ram.*]` で名前を付けて使う） |

`oam` の番地は fc.toml の `[define.oam] ADDR` で変えられる。ほかの変数や fc の領域と重ねてはいけない。
ゼロページに変数を置くなら `@(segment: "ZEROPAGE")` を使う。`@(address: …)` で fc の使う場所に重ねるとエラーになる。
同じ領域を別の型で使う場合は[ストレージの別名](./language#storage-alias)を使う。

## 初期化

起動時に `$0000`〜`$07FF` を 0 にしてから `main` を呼ぶ。通常のグローバル変数はこの範囲にあるので 0 で始まる。
カートリッジ RAM に置いた変数は自動で 0 にしない。セーブデータの有効性の確認や、必要な初期化はプログラムで行う。
`@(address: …)` で参照する I/O の値も、通常の変数の初期値とは別である。

## 関数の変数の置き場所

再帰しない関数の引数・戻り値・変数は、関数ごとの決まった場所（静的フレーム）に置く。呼び出しの関係を見て、同時に使われない関数どうしで
同じ場所を使い回すので、使う領域は「いちばん深い呼び出しの連鎖の分」くらいで済む。ゼロページに入るだけ置き、残りは RAM に置く。
入り切らなければビルドのエラーになる。

再帰する関数と `@(abi: "stack")` の関数の変数はスタックに置く。関数ポインタで呼ぶ関数や `@(interrupt)` の関数は、呼び出しのたびに
自分の場所へ引数を写す。関数ポインタの型を `@bitcast` で変えて呼ぶ再帰は検出できないので、`@(abi: "stack")` を指定する。

`main` のモジュールの `@(static_zp: N)` / `@(static_ram: N)` で予約量を変更できるが、グローバル変数などと合わせて RAM に収める必要がある。
アセンブリや割り込みから呼ぶ場合の制約は[アセンブリとの連携](./assembly)を参照。

## 使われないものは出力しない

`main`・割り込み・`@(symbol: …)` の関数・アドレスを取られた関数から呼び出しをたどって届かない関数は、ROM に入らない（`public` でも同じ）。
使われない private の変数と配列の定数も領域を取らない。ただし `@(symbol: …)` を付けたものや、置き場所を指定した変数は残す。
`fcc build -d` で出力しなかった関数を並べる。
