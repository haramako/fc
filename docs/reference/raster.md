# 走査線の IRQ で画面を分ける

MMC3 の走査線の IRQ（[mmc3.irq](./std/nes/mmc3)）で画面を横の帯に分け、帯ごとにスクロールなどを変えるときの決まりと注意。
IRQ の中の処理はアセンブリで書く（[割り込みから呼ぶ関数](./assembly#interrupts)）。実例は
[statusbar](https://github.com/haramako/fc/tree/main/examples/statusbar)（上の帯を止めて下だけ横にスクロール）と
[wave](https://github.com/haramako/fc/tree/main/examples/wave)（8 走査線ごとに横のスクロールを変える）。

細かい仕組みは nesdev wiki の [MMC3 の IRQ](https://www.nesdev.org/wiki/MMC3#IRQ_Specifics) と
[スクロールの分割](https://www.nesdev.org/wiki/PPU_scrolling#Split_X/Y_scroll)、走査線の中の時刻は
[PPU の描画](https://www.nesdev.org/wiki/PPU_rendering) を参照。

## 走査線の数え方 {#counter}

- MMC3 は、PPU がパターンを読む番地の A12 が 0 から 1 に変わるたびに 1 つ数える。背景を `$0000`、スプライトを `$1000` に置くと、
  描画中の走査線ごとに 1 回（走査線の終わりのほう、スプライトのパターンを読む所）数える。**この置き方にする**
  （`frame.ctrl |= nes.CTRL_SPR_1000;`）。逆の置き方や 8×16 のスプライトでは、数え方が 1 走査線ずれたり走査線ごとに変わったりする
- 数えるたびに、数が 0 か「入れ直し」（`$C001` に書いた後）なら `$C000` の値を入れ直し、そうでなければ 1 減らす。0 になったら IRQ
- `mmc3.irq(n)` を vblank の間に呼ぶと、描画の前の走査線（pre-render。これも数える）で n を入れ直し、画面の上から n 本を
  描き終わる所で IRQ が来る
- 背景もスプライトも止めた（PPUMASK の両方を消した）走査線は、PPU がパターンを読まないので数えない。QuickNES は背景だけを
  止めた走査線でも数えなかった。QuickNES で確かめるなら、帯の途中で背景を止めない
- `$C000` を 0 にしたときの動きは MMC3 の版で違う（走査線ごとに IRQ が来る版と、1 回だけの版がある）。間を 0 にしない

## IRQ の中で次の IRQ を仕掛ける {#chain}

帯が 3 つ以上なら、IRQ の中で次の IRQ を仕掛ける（`$E000` で受け取り、`$C000` に次までの数、`$C001` に書いて入れ直し、`$E001` で許す）。

- IRQ が来たときには、その走査線の分はもう数えてある。入れ直しは次に数える所で起き、そこから数え始める。次の境目まで d 走査線なら、
  次の走査線の数えに間に合えば `$C000` は d − 1
- 1 走査線は約 113.7 CPU サイクル。fc の IRQ の入口（レジスタを積み、`mmc3` の受け取りを通って `irq_hook` を呼ぶ）を通り、先に
  スクロールを書いてから `$C001` を書くと、次の走査線の数えに間に合わず、もう 1 本遅れる（d − 2 にする）。QuickNES ではこの形で
  d − 2 が合った（[fc を使うプロジェクトの報告](https://github.com/haramako/fc/issues/15)）
- 境目が近すぎて差が 0 以下になると、IRQ の連鎖が止まり、その下の帯（HUD など）が切り替わらない。帯の間は 3 走査線以上空ける

## 縦と横のスクロールを変える {#scroll}

描画の途中で `$2005` を書いても、縦のスクロールは次の画面まで効かない。縦も変えるには、次の 4 回をこの順で書く
（nesdev wiki の [Split X/Y scroll](https://www.nesdev.org/wiki/PPU_scrolling#Split_X/Y_scroll)）。

| 順 | 番地 | 書く値 |
|---|---|---|
| 1 | `$2006` | ネームテーブルの番号 × 4（`$00` / `$04` / `$08` / `$0C`） |
| 2 | `$2005` | Y |
| 3 | `$2005` | X |
| 4 | `$2006` | `((Y & $F8) << 2) \| (X >> 3)` |

- 4 回目でその場で番地が入れ替わる。後の 2 回は走査線の右の端の後（hblank、dot 256〜320）に書くと乱れが出ない
- 書く値は先に計算してレジスタ（とスタック）に用意しておき、4 回を続けて書く（間に計算を挟むと、書き終わりが遅れて走査線をまたぐ）
- IRQ は走査線の終わりのほうで来て、入口を通る間に次の走査線の途中まで進む。QuickNES では、境目の 2 走査線前に IRQ を起こし、
  縦の位置を 1 引いて書くと、位置が合い境目のちらつきも出なかった（hblank より前に書き終わると、その走査線の終わりで PPU が縦の
  位置を 1 進める。1 走査線前に起こすと、境目の走査線の左側に前の行が出た）
